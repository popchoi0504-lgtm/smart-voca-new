## 0. 이번 주에 꼭 해 볼 것 (11-30 23:59까지)

앱이 완성되지 않아도 됩니다. **아래 7가지를 이번 주에 끝내고 1차 제출하세요.** 서버에 올라가는지는 지금 확인해야 고칠 시간이 있습니다.

아래 순서대로 하나씩 하세요. 이번 주 안에 이 목록이 **체크리스트**로 바뀝니다. 그때부터 끝낸 항목을 직접 체크할 수 있습니다.

### 1. GitHub 공개 리포를 만듭니다

개인 구글 계정으로 가입한 GitHub 계정을 씁니다. 리포는 **Public**으로 만듭니다.

1. github.com 에 개인 구글 계정으로 로그인합니다. 계정이 없으면 이때 가입합니다.
2. 오른쪽 위 **+** → **New repository** 를 누릅니다.
3. 이름(예: `voca-web`)을 적고 **Public** 을 고릅니다. **Add a README file** 을 체크하고 **Create repository** 를 누릅니다.

> 자세히: 「소프트웨어 요건」 4.1 리포와 제출

### 2. 리포 뼈대를 올립니다

`README.md`, `CLAUDE.md`, `docs/`(기획서부터)를 넣습니다. 앱은 첫 화면 하나만 나와도 됩니다.

1. 리포를 내 PC로 받습니다 (GitHub Desktop 또는 `git clone`).
2. `docs/` 에 프로젝트 기획서를 둡니다. 이름은 `기획_yymmdd_제목 v0.1.md` 처럼 방법론 규칙을 따릅니다.
3. `CLAUDE.md` 에 작업 방식을 적습니다: 방법론 참조, 산출물 위치, 작업 흐름(분석 → 설계 → 구현 → 테스트).
4. 첫 화면 하나가 나오는 앱 코드를 넣고 커밋·push 합니다.

> 자세히: 「소프트웨어 요건」 4.2 개발 방법론 산출물 · 4.3 CLAUDE.md

### 3. `Dockerfile` 을 만듭니다

「Dockerfile 생성 프롬프트」를 AI에게 붙여 넣어 만들고, 리포 루트에 둡니다.

1. 「Dockerfile 생성 프롬프트」의 **공통 프롬프트**를 복사 버튼으로 복사합니다. 내 스택(Flask·FastAPI·Express)의 추가문도 「Dockerfile 생성 프롬프트」에서 함께 복사합니다.
2. AI 도구에 내 리포를 열어 둔 채 붙여 넣습니다.
3. 만들어진 `Dockerfile` 을 리포 루트에 둡니다. `.dockerignore`·`.gitattributes` 도 함께 둡니다.

> 자세히: 「Dockerfile 생성 프롬프트」 쓰는 법 · 「Dockerfile 구성」 3.1 필수 규칙

### 4. 점검 워크플로를 넣습니다

내려받은 `docker-check.yml` 을 **고치지 않고** `.github/workflows/docker-check.yml` 에 둡니다.

1. 이 페이지의 **`docker-check.yml` 내려받기**를 누릅니다.
2. 리포에 `.github/workflows/` 폴더를 만들고 그 안에 넣습니다. 파일 내용은 고치지 않습니다.
3. 커밋하고 push 합니다. 이후 push 할 때마다 자동으로 돕니다.

> 자세히: 「Dockerfile 구성」 4.1 넣는 법

### 5. push 하고 Actions 탭에서 초록(✅)을 확인합니다

빨강(❌)이면 실패한 단계의 로그를 AI에게 보여 주고 고칩니다.

1. GitHub 리포의 **Actions** 탭을 엽니다.
2. 맨 위 실행 기록을 누릅니다. 초록 체크면 통과입니다.
3. 빨간 X면 빨간 단계를 열어 메시지를 봅니다. 맨 아래 "실패하면 앱 로그"에 내 앱의 오류가 나옵니다. 그 내용을 AI에게 보여 주고 고친 뒤 다시 push 합니다.

> 자세히: 「Dockerfile 구성」 4.2 결과 보는 법 · 「Dockerfile 구성」 5. Windows에서 자주 생기는 문제

### 6. 시크릿 창에서 리포 주소가 열리는지 확인합니다

로그인하지 않아도 보여야 공개 리포입니다.

1. 브라우저에서 시크릿 창을 엽니다 (크롬 `Ctrl+Shift+N`).
2. 내 리포 주소 `https://github.com/<아이디>/<리포>` 를 엽니다.
3. 404가 나오면 리포 **Settings** → **General** 맨 아래에서 **Change visibility** → **Public** 으로 바꿉니다.

> 자세히: 「공지」 5. 꼭 지킬 것

### 7. 이 페이지의 제출 폼으로 1차 제출합니다

초록이 뜬 커밋의 SHA를 적습니다.

1. 리포의 커밋 목록에서 초록 체크가 붙은 커밋의 복사 버튼을 누릅니다. 40자 SHA가 복사됩니다.
2. 이 페이지 맨 아래 제출 폼에 리포 URL, SHA, 앱 이름, 한 줄 설명을 적고, 공개 확인과 계정 자가 신고에 체크합니다.
3. 저장합니다. 고친 뒤에는 새 SHA로 다시 저장합니다.

> 자세히: 「공지」 6. 제출 방법 · 「Dockerfile 구성」 4.3 제출할 커밋

## 1. 과제

수업에서 만든 단어장 프로그램을 **웹 앱**으로 다시 만듭니다. 학교 서버에 올려 실행되게 하는 것까지가 과제입니다.

- 단어 등록, 암기, 시험, 학습 진척 통계를 만듭니다. 이력은 **DB**에 저장합니다.
- AI 도구를 써도 됩니다. 대신 개발 방법론에 따라 문서와 코드를 함께 키워 가세요. 그 흔적은 `docs/`·`CLAUDE.md`·커밋 이력으로 확인합니다.
- 결과는 **GitHub 공개 리포** 하나로 냅니다.
- 서버에 올라간 앱은 `/2026/voca-<학번>/` 주소로 열립니다.

## 4. 평가

- **기본 기능**과 **제출 요건**을 모두 채우면 만점입니다.
- **도전 기능**(로그인, 다른 계정 이력 보기, 설정)은 **가산점**입니다. 도전 기능을 했다고 해서 빠진 기본 기능이 채워지지는 않습니다. 기본부터 완성하세요.
- 평가 항목
  - 기능: 서버에 올라간 앱 시연, 코드, DB
  - 문서: `docs/` 개발 산출물, `CLAUDE.md`, 커밋 이력
  - 배포: 서버에서 빌드·실행되는지, 점검 워크플로 통과
  - 계정: 개발 서비스 계정 관리
- **Dockerfile 필수 규칙(R-01~R-10)을 어기면 서버에 올라가지 않습니다.** 그러면 시연 평가를 받기 어렵습니다. 점검 워크플로를 꼭 통과시키세요.
