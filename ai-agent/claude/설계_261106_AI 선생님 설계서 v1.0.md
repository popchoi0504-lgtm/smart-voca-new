# AI 선생님 설계서 (이슈 #16)

**파일 위치**: `ai-agent/claude/설계_261106_AI 선생님 설계서 v1.0.md`
**작성일**: 2026-11-06
**버전**: v1.0
**설명**: 화면 오른쪽 아래 선생님 아이콘으로 현재 단어를 Gemini 에게 물어보는 기능의 요구사항·구조·결정·테스트 계획.

---

## 1. 배경과 목표

- 학습 중 모르는 단어를 바로 물어볼 곳이 없고, 무료/프리미엄을 가르는 혜택이 "단어 수" 하나뿐이다.
- 목표: 단어 하나에 대해 쉬운 설명, 비슷한 단어와의 차이, 다른 예문을 AI 가 알려 주는 기능을 작게 넣는다. 하루 횟수로 무료/프리미엄을 구분한다.
- 범위 밖: 자유 대화, 작문 첨삭, 음성, 대화 기록 저장.

## 2. 요구사항 (요구사항 명세서 v1.1 에 반영할 항목)

| ID | 요구사항 | 비고 |

| FR-AI-03 | 퀴즈 화면에서는 그 문제를 맞히거나 "정답 확인"을 누른 뒤에만 선생님을 쓸 수 있다. | 단어가 정답이므로 풀기 전 노출 방지. **화면에서 막고, 서버는 "배운 단어인지"만 검사한다**(구현 중 결정, ADR 3 참고) |

| FR-AI-08 | 영어 단어 학습과 무관한 질문은 정중히 거절한다. | 시스템 지시문으로 고정 |

## 3. 구조

```
화면: TeacherButton(아이콘) → TeacherPanel(대화) → api/ai.js
   ↓ POST /api/ai/teacher
서버: routers/ai.py → services/ai_service.py
        ├ 로그인·한도 검사(ai_usages 표)
        ├ 단어 조회(words 표) + 퀴즈면 풀이 여부 검사(review_logs)
        └ app/ai/provider.py(규격) ← gemini_provider.py / fake_provider.py
```

- 결제(`app/payments/`)와 같은 "담당자 교체" 방식. 테스트와 시연 대비는 가짜 담당자, 실제는 Gemini 담당자. 선택은 `AI_PROVIDER`(gemini / fake).
- 새 파일(예정): `app/ai/provider.py`, `gemini_provider.py`, `fake_provider.py`, `prompts.py`(시스템 지시문과 빠른 버튼 문장), `app/models/ai_usage.py`, `app/schemas/ai.py`, `app/services/ai_service.py`, `app/routers/ai.py`, 화면 `components/TeacherButton.jsx`·`TeacherPanel.jsx`, `api/ai.js`.

## 4. 데이터

새 표 `ai_usages` (사용자·날짜별 횟수). 개발 DB 변경은 Alembic, 적용 전 대표 승인.

| 열 | 타입 | 설명 |
|----|------|------|
| user_id | FK(users), PK 일부 | 삭제 시 함께 삭제 |
| usage_date | date, PK 일부 | 한국 날짜 |
| call_count | smallint (0 이상) | 성공한 호출 수 |
| (기본 키) | (user_id, usage_date) | 하루 한 행. 별도 id 열은 두지 않음 |

횟수 확인과 증가는 SQL 한 문장(없으면 만들고, 한도 미만일 때만 +1)으로 처리해 동시에 눌러도 한도를 넘지 않는다. 답을 못 받으면 -1 로 돌려준다.

대화 내용은 저장하지 않는다(개인정보 최소화).

## 5. API (인터페이스 정의서 4.7 로 추가 예정)

`POST /api/ai/teacher` — 로그인 필요

- 요청: `{ "word_id": 123, "kind": "simple" | "compare" | "example" | "ask", "question": "…(kind=ask 일 때만, 1~200자)", "context": "study" | "quiz" }`
- 성공 200: `{ "answer": "…", "remaining_today": 7, "daily_limit": 10 }`
- 오류(공통 모양 `{"error": {"code", "message"}}`):

| HTTP | 코드 | 상황 |
|------|------|------|
| 401 | UNAUTHORIZED | 로그인 안 함 |
| 404 | WORD_NOT_FOUND | 없는 단어 |
| 409 | WORD_NOT_LEARNED | context=quiz 인데 아직 배우지 않은 단어(퀴즈 API 와 같은 규칙) |
| 403 | WORD_NOT_AVAILABLE | context=study 인데 요금제 범위 밖 단어 |
| 422 | VALIDATION_ERROR | kind·question 형식 오류 |
| 429 | AI_LIMIT_REACHED | 하루 한도 초과 |
| 503 | AI_UNAVAILABLE | 꺼짐 또는 외부 호출 실패·시간 초과 |

## 6. 설정 (.env.example 에 추가)

`AI_PROVIDER`(gemini|fake), `GEMINI_API_KEY`(비워 둠), `GEMINI_MODEL`, `AI_TEACHER_ENABLED`(true), `AI_FREE_DAILY_LIMIT`(10), `AI_PREMIUM_DAILY_LIMIT`(50).

## 7. 결정 기록 (ADR)

1. **서버가 Gemini 를 호출한다(화면에서 직접 호출 금지)**
   - 배경: 키가 화면 코드에 들어가면 누구나 훔쳐 쓸 수 있다.
   - 대안: 화면에서 직접 호출 → 빠르지만 키 노출. 서버 호출 → 키 보호, 횟수 제한 가능.
   - 근거: 서버 호출. 한도 관리와 프롬프트 고정도 서버에서만 가능하다.
2. **자유 대화 대신 빠른 버튼 3종 + 짧은 질문**
   - 대안: 긴 대화 → 주제 이탈·프롬프트 조작·개인정보 입력 위험이 커지고 비용·한도 소모가 큼.
   - 근거: 발표 일정(11-13)과 안정성. 단어 하나에 집중한 작은 기능이 시연에도 안전하다.
3. **퀴즈는 풀이 후에만 (화면에서 막음, 서버는 배운 단어만 확인)**
   - 근거: 단어가 곧 정답이라 풀기 전 노출은 퀴즈를 무의미하게 만든다. 힌트 1~3단계가 이미 있다.
   - 구현 중 바꾼 점: 처음에는 서버도 "풀었는지"를 검사하려 했지만, 첫 시도가 오답이면 기록되고 그 뒤 정답은 "연습"이라 기록되지 않아 서버가 풀이 여부를 믿을 만하게 알 수 없다. 억지로 검사하면 정답을 맞힌 사용자가 막히는 문제가 생긴다.
   - 대안: 서버에 "오늘 정답 처리한 단어" 상태를 따로 저장 → 표·로직이 늘고, 속여도 본인 퀴즈 학습에만 영향이라 이번 범위에서는 제외. 확장 단계 과제.
4. **하루 횟수는 DB 표로 관리(무료 10, 프리미엄 50)**
   - 대안: 메모리 카운터 → 서버를 켜고 끌 때마다 0 으로 돌아감.
   - 근거: 결제 유인(대표 결정 2026-11-06: 무료 10회, 더 쓰려면 유료). 프리미엄 50회는 제안값이며 .env 로 조정한다.
5. **무료 Gemini 키 사용과 개인정보 최소화**
   - 사실: 공식 가격 문서에 무료 이용분은 "제품 개선에 사용", 유료는 미사용으로 표기. 무료 한도는 모델별이고 예고 없이 바뀐 사례가 포럼에 있음(2026-11-06 확인).
   - 근거: 단어·질문만 보내고, 입력칸에 경고를 붙인다. 정식 출시 때는 유료 키로 전환하는 것을 검토한다.
6. **모델 이름은 코드에 쓰지 않고 `GEMINI_MODEL` 로 둔다**
   - 근거: 검색 결과에서 모델 이름이 문서마다 달랐다. 키를 넣은 뒤 목록 조회로 확인해 값을 정한다.
7. **실패해도 앱은 계속 동작, 횟수는 성공한 호출만 차감**
   - 근거: 외부 서비스 문제로 사용자가 불이익을 받으면 안 된다. 발표 중 장애에 대비한 끄기 스위치 포함.

## 8. 테스트 계획 (가짜 담당자로 외부 호출 없이)

- 한도: 무료 10회째 성공·11회째 429, 프리미엄은 50회, 다음 날(날짜 변경) 초기화, 실패한 호출은 차감 안 됨.
- 권한: 로그인 없음 401, 없는 단어 404, 무료 범위 밖 단어 403.
- 퀴즈 규칙: 풀지 않은 단어 403, 정답·정답 확인 후 200.
- 입력: kind 가 ask 인데 질문 없음/201자 422.
- 담당자 실패: 시간 초과·오류 시 503, 횟수 미차감, 다른 API 정상.
- 끄기: `AI_TEACHER_ENABLED=false` 면 503.
- 로그 안전: 키·질문 원문이 로그에 없음(기존 test_log_safety 방식으로 추가).
- 일부러 고장 내기: 한도 검사 제거, 퀴즈 규칙 제거, 실패 시 차감, 키 로깅 → 각각 테스트가 잡는지 확인.
- Gemini 담당자는 응답 해석(정상·차단·빈 응답·오류)을 가짜 HTTP 응답으로 단위 테스트. 실제 호출은 대표 승인 후 1~2회 수동 확인.

## 9. 진행 순서

1. 이 설계서와 이슈 #16(발행 완료). 2. 대표가 `.env` 에 키 입력(대화창에 붙여넣지 않음). 3. `ai_usages` 표 Alembic 적용(승인). 4. 서버(규격·가짜·한도·API)와 테스트. 5. Gemini 담당자와 첫 외부 호출(승인). 6. 화면(아이콘·패널). 7. 확인·일지·질문 모음·요구사항 반영.
