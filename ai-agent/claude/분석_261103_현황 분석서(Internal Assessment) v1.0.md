## 6. 가정 및 제약

### 6.1 제약
1. **시간**: 구현 6일. 평일 약 5시간.
2. **비용**: 유료 서비스 사용 불가. AI API, 클라우드, 유료 DB 호스팅 사용 안 함.
3. **인력**: 대표 단독. 팀원은 청중이자 테스트 참여자.
4. **환경**: 대표 노트북에서 로컬 실행. 외부 접속 없음.
5. **법적**: 단어 데이터는 저작권 문제가 없어야 함.

### 6.2 가정
1. 팀원은 대표 노트북 화면에서 직접 사용한다. 동시 접속 부하는 작다.
2. 개발 중 새 도구 설치(PostgreSQL 등)는 대표 승인 후 진행한다.
3. 이전 버전 저장소의 코드는 이번 프로젝트와 독립적이다.

### 7.1 단어 데이터 작성 방침에 대한 분석 (Claude 의견)

대표가 "단어는 법적 문제 없이 Claude가 만든다"고 결정했다. 이에 대해 확인이 필요한 점이 있다.
- **장점**: 단어장의 구성이나 설명을 그대로 옮기지 않으므로 저작권 위험이 줄어든다. 비용도 들지 않는다.
- **위험**: Claude가 작성한 뜻과 예문에 **오류**가 있을 수 있다. 특히 "토익에서 실제로 자주 나오는 단어인가"는 공식 빈도 자료로 검증하기 어렵다. 서비스 품질에 직접 영향을 준다.
- **대응 제안**: (a) 처음에는 소규모(예: 약 300~500개)로 시작해 품질을 확인하고, (b) 단어 목록은 공개 라이선스 빈도 자료와 대조해 검증하며, (c) 대표가 샘플 일부를 직접 확인한다. 규모와 방식은 환경 분석서 조사 후 결정한다.
- **결정 필요**: 단어 개수와 품질 확인 방식 `[대표 결정, 환경 분석서 후]`
