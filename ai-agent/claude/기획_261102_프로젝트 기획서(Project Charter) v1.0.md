## 2. 배경과 목적

### 2.1 배경
- 사업 아이템 후보를 겸한 팀 프로젝트다. 팀원 5명의 역량을 서로 확인하는 자리이며, 대표는 이 프로젝트로 본인의 역량을 보여주려 한다.
- 팀원은 이번 프로젝트에 개발·데이터·디자인으로 참여하지 않는다. 팀원은 발표 청중이자 사용 테스트 참여자다.

### 2.2 목적
1. 토익 단어 학습의 실제 불편을 해결하는 서비스를 끝까지 동작하게 만든다.
2. 상용화 가능한 수준의 구조(계정, DB, 보안, 테스트, 구독 구조)를 갖춘다.
3. 대표가 모든 기술 선택의 이유를 이해하고 직접 설명할 수 있게 한다. (문서화와 결정 기록이 이를 지원한다.)

## 3. 문제 정의

대표 본인의 토익 단어 암기 경험에서 나온 불편이다.

| # | 불편 | 원인 추정 |
|---|---|---|
| P1 | 단어 양이 너무 많다 | 우선순위 없이 전체를 순서대로 본다 |
| P2 | 외워도 금방 까먹는다 | 잊는 시점에 맞춘 복습이 없다 |
| P3 | 복습 방법을 몰라 매번 처음부터 다시 본다 | 무엇을 복습할지 스스로 판단해야 한다 |
| P4 | 지루하고 재미가 없다 | 단순 반복 중심의 학습 경험 |
| P5 | 하루에 짧게 여러 번 쓰고 싶다 | 긴 학습 세션을 전제로 한 구성 |

※ 위 항목은 대표 1인의 경험이다. 다른 사용자에게도 같은지는 팀원 사용 테스트에서 일부 확인할 수 있으나 정량 검증은 이번 범위 밖이다.

## 4. 타깃

- **MVP 타깃**: 토익 준비생. 단어장으로 단어를 외우는 사람.
- **이후 확장 후보**: 토플 준비생, 초중고생.
- 확장 후보를 미룬 이유는 7장 결정 기록 D-1 참고.

## 5. 핵심 가치와 차별점

### 5.1 핵심 가치
> "까먹을 만할 때 정확히 다시 보여주고, 하루 5분 안팎으로 끝나게 한다."

| 핵심 가치 | 대응하는 문제 |
|---|---|
| 복습 시점을 서비스가 대신 계산 (간격 반복) | P2, P3 |
| 오늘 해야 할 단어만 골라서 제시 | P1, P3 |
| 짧은 세션, 중단 후 이어하기 | P5 |
| 지루함을 줄이는 장치 (연속 학습일, 진행 시각화 등, 구체안은 설계 단계) | P4 |

### 5.2 시장 상황 (1차 웹 조사, 2026-11-02, 표준 검색 3건)
- 말해보카는 앱스토어 설명 기준 망각 곡선 기반 자동 복습을 제공한다. 표기 가격은 1개월 19,500원, 1년 119,000원이며 최신 여부는 미확인이다.
- 해커스토익 기출보카는 교재 연동, 게임형 암기, 외운/못 외운 단어 분리 복습을 제공한다. (앱스토어 소개 문구 기준)
- Anki 공식 문서는 SM-2와 FSRS 두 가지 복습 스케줄러를 제공한다고 밝힌다. FSRS가 SM-2보다 월등하다는 근거는 대부분 업체 마케팅이며 독립 검증은 확인하지 못했다.
- 클래스카드, 퀴즐렛은 조사하지 못했다. `[추가 조사 필요]`

### 5.3 차별점에 대한 솔직한 평가
- 간격 반복 자체는 시장에 이미 있어 **기능만으로는 차별점이 되지 않는다.**
- 이번 프로젝트의 차별점은 "토익 단어 암기라는 한 가지 목적에 집중해 복습 경험(적절한 시점, 짧은 세션, 지루하지 않음)의 완성도를 높이는 것"이다.
- "기존 앱 대신 왜 이걸 써야 하나"라는 질문에 대한 답은 아직 약하다. `[보강 필요: 토익 빈출도 기반 학습 순서 등 후보를 분석 단계에서 검토]`

## 6. 범위

### 6.1 포함 (In Scope)
- 회원가입·로그인
- 단어 학습 (플래시카드 형태)
- 퀴즈 (뜻 맞히기 등 기본 형태)
- 간격 반복 방식의 복습 스케줄링
- 학습 기록 확인 (진행 현황)
- 구독 요금제 구조와 **테스트 모드** 결제 시연
- 자동 테스트, 에러 처리, 로그
- 실행 방법 문서화 (설정과 코드 분리)

### 6.2 제외 (Out of Scope)
- 인터넷 공개 배포 (도메인, 서버, HTTPS)
- Docker 설정 (시간이 남을 때만 검토, 필수 아님)
- 실제 결제 연동 (사업자등록, 심사 필요)
- 모바일 대응·반응형, 외부 기기 접속
- 토플·초중고생 콘텐츠
- 수천 명 동시 접속 대응 (구조 설명만)
- 시험 형식 문제 연습, AI 예문 생성 (시간이 남으면 1개만 추가 검토)

### 6.3 검토 항목
- 이용약관·개인정보처리방침 초안: 상용화 관점에서 필요하나 우선순위 `[대표 결정]`

## 7. 결정 기록 (ADR 성격)

### D-1. MVP 타깃을 토익으로 한정
- **배경**: 초중고생과 토익·토플은 결제 주체, 단어 범위, 법적 부담이 다르다.
- **대안**: ① 토익·토플 중 토익 ② 초중고생 ③ 전체 동시 진행
- **결정 근거**: 토익은 사용자가 본인이 결제하는 구조라 구독 전환이 단순하고, 만 14세 미만 개인정보 동의 같은 법적 부담이 적으며, 단어 데이터를 직접 구성할 수 있다. 대표 본인이 토익 단어를 공부 중이라 문제를 직접 겪고 있다. 전체 동시 진행은 혼자 2주 범위를 넘는다.
- **결정**: 토익 (대표 승인 2026-11-02). 초중고생과 토플은 확장 단계.

### D-2. 차별점은 집중형(암기 경험의 완성도)으로 한다
- **배경**: 간격 반복은 이미 시장에 있어 기능 자체가 차별점이 되기 어렵다.
- **대안**: ① 집중형: 암기 경험 완성도 ② 조합형: 간격 반복 + 시험 형식 연습 또는 AI 예문
- **결정 근거**: 보카 서비스의 본질은 단어 암기이고, 혼자 2주에 조합형은 품질 위험이 크다. AI 예문은 API 비용이 구독료 대비 수익성에 영향을 줄 수 있다.
- **결정**: 집중형 (대표 승인 2026-11-02). 시간이 남으면 조합형 요소를 1개만 추가 검토.
- **위험**: 5.3의 약점(왜 이걸 써야 하나)이 남아 있다.

### D-3. 배포는 로컬 실행으로 한정
- **배경**: 팀원이 대표 노트북에서 직접 사용해 보는 방식으로 발표한다.
- **대안**: ① 로컬 실행 + 실행 문서화 ② Docker 설정 포함 ③ 클라우드 공개 배포
- **결정 근거**: 시연 조건에 인터넷 접속이 필요 없고, 서버 설정에 쓸 시간을 기능과 품질에 쓰는 것이 낫다.
- **결정**: ① (대표 승인 2026-11-02).

### D-4. 기술 스택은 FastAPI + PostgreSQL + React (잠정)
- 상세는 `검토_261102_기술스택 v1.0.md` (ADR-001) 참조.
