## 2. 경쟁 서비스

### 2.1 확인된 것 (1차 웹 조사, 출처는 기획서 5.2와 동일)
| 서비스 | 확인된 특징 | 한계 |
|---|---|---|
| 말해보카 | 앱스토어 설명 기준 망각 곡선 기반 자동 복습, 초기 20문제로 수준 파악. 표기 가격 1개월 19,500원, 1년 119,000원 | 가격 최신 여부, 토익 전용 단어장 여부 미확인 |
| 해커스토익 기출보카 | 교재 연동, 게임형 암기, 외운/못 외운 단어 분리 복습 | 앱스토어 소개 문구 기준 |
| Anki | SM-2, FSRS 스케줄러 제공 (공식 문서) | 범용 플래시카드이며 토익 전용 아님 |
| FSRS 앱들(예: LexPilot) | FSRS 사용을 내세움 | 업체 주장이라 독립 검증 아님 |

### 2.2 조사하지 못한 것
- 클래스카드, 퀴즐렛 `[미확인]`. 앱을 직접 써 본 대표의 의견이 더 정확할 수 있다.
- 각 서비스의 실제 사용자 불만. 이번 조사는 공식 소개 문구 중심이다.

### 2.3 시사점
- 간격 반복과 게임 요소는 이미 있다. 따라서 기획서 5.3의 평가대로 **차별점이 약하다는 점은 변하지 않는다.**
- 이번 프로젝트에서 새로 시도하는 퀴즈 3단계 힌트(기획서 5.4)는 조사한 서비스의 소개 문구에서는 확인하지 못했다. 다만 "없다"고 단정할 근거는 없으므로 발표에서는 "조사한 범위에서는 확인하지 못했다"로 말해야 한다.

## 3. 단어 데이터 출처

대표는 "단어는 법적 문제 없이 Claude가 작성한다"고 결정했다(현황 분석서 7.1). 이를 돕는 외부 자료를 조사했다.

### 3.1 TOEIC Service List (TSL)
- 토익 시험과 교재를 분석한 말뭉치(corpus)에서 만든 약 1,200단어 목록이다. 저자는 Browne와 Culligan(2016)이다.
- 출처 사이트가 밝힌 바로는 **토익 시험의 약 99%를 커버**한다. 같은 사이트의 일반 영어 목록 NGSL은 토익의 약 94%를 커버한다.
- 라이선스는 **CC BY-SA 4.0**(저작자 표시 + 동일조건 변경허락)이다.
- 빈도 통계는 "TSL 1.2 with basic statistics" 파일에만 들어 있다.
- 해커스 같은 시중 단어장과는 별개의 공개 자료다.

### 3.2 CC BY-SA 4.0 이 의미하는 것 (법률 자문이 아니라 일반 설명)
| 조건 | 뜻 | 이 프로젝트에 미치는 영향 |
|---|---|---|
| 저작자 표시(BY) | 원 저작자와 라이선스를 밝혀야 함 | 서비스 화면 또는 문서에 출처 표기 필요 |
| 동일조건(SA) | 원 자료를 바탕으로 만든 **변경물**을 같은 라이선스로 공개해야 함 | TSL을 바탕으로 만든 단어 데이터가 "변경물"에 해당하면 그 데이터를 CC BY-SA로 공개해야 할 수 있음 |
| 상업적 이용 | 허용 | 구독 서비스로 쓰는 것 자체는 막히지 않음 |

`[미확인]`: 단어 **목록(어떤 단어를 고르는가)** 만 참고하고 뜻과 예문은 Claude가 직접 쓰는 경우, 결과 데이터가 SA 조건의 "변경물"에 해당하는지는 이번 조사로 판단할 수 없다. 상용 서비스를 실제로 내기 전에 라이선스 원문 확인 또는 저자 문의가 필요하다. 이번 발표 범위(로컬 시연)에서는 위험이 낮지만, "상용화 가능"을 말하려면 이 점을 정리해야 한다.

### 3.3 선택지
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | Claude가 단어, 뜻, 예문을 모두 직접 작성하고 TSL은 **누락 점검에만** 참고 | 대표 지시와 일치, 저작권 위험이 가장 낮음 | "토익 빈출 단어"의 근거가 약함 |
| B | TSL 단어 목록을 뼈대로 쓰고 뜻·예문은 Claude가 작성. 출처 표기 + 필요 시 데이터 CC BY-SA 공개 | 토익 시험 기반이라는 설득력, 빈도 순서 학습이 가능 | SA 조건의 영향 검토 필요, 라이선스 의무 준수 필요 |
| C | 둘 다 쓰지 않고 순수 임의 선정 | 라이선스 이슈 없음 | 품질 근거 없음 |

Claude 의견: **B를 우선 검토**한다. 토익 기반 빈도 자료가 있다는 사실이 차별점 보강(기획서 5.3 `토익 빈출도 기반 학습 순서`)에도 연결된다. 다만 SA 조건은 대표가 이해하고 결정해야 한다.

### 3.4 단어 작성 품질 위험
- Claude가 작성한 뜻과 예문에는 오류가 있을 수 있다. 샘플 검수가 필요하다.
- 규모 결정 필요: TSL은 약 1,200단어이므로, 전체를 작성할지 일부만 할지 `[대표 결정]`.

## 4. 복습 알고리즘

| 항목 | SM-2 | FSRS |
|---|---|---|
| 설명 | 오래된 간격 반복 공식. 단순함 | 더 최신 방식. 기억 모델을 사용 |
| Anki 지원 | 지원 | 지원 (v23.10 이후) |
| 구현 | 직접 구현 가능. 공식이 단순해 대표가 설명하기 쉬움 | 파이썬 라이브러리 `fsrs` (MIT 라이선스) 사용 가능 |
| 우려 | 모델이 단순함 | 라이브러리의 마지막 릴리스가 2024년 9월(3.1.0)로 보도됨 `[미확인: 이후 버전]`, Python 3.14 지원 미확인, 내부 계산을 설명하기 어려움 |
| 근거 수준 | 널리 사용됨 | 우월하다는 주장은 대부분 업체 마케팅이며 독립 검증은 확인하지 못함 |

시사점: 이번 프로젝트는 "대표가 설명할 수 있어야 한다"가 최우선이므로 **SM-2 계열을 직접 구현하는 안**이 유력하다. FSRS는 "확장 가능성"으로 언급할 수 있다. 결정은 설계 단계의 ADR에서 한다. 힌트 사용(기획서 D-5)이 복습 간격에 미치는 영향도 이때 함께 정한다.

## 5. 결제 시연 (구독 구조)

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 토스페이먼츠 테스트 키로 연동 | 실제 결제 흐름과 비슷한 화면 | 검색 요약에서 "신청 전 테스트 키로 연동"과 "실제로 결제가 나지 않음"은 확인됐으나 **공식 문서는 직접 확인하지 못함**. 계정 가입·무료 여부 `[미확인]`. 정기결제(구독)가 같은 방식인지도 미확인 |
| B | 서비스 안에서 **가짜 결제 화면과 구독 상태 관리**를 직접 구현 | 외부 의존 없음, 무료, 대표가 전부 이해하고 설명 가능 | 실제 결제가 아니라는 점을 발표에서 분명히 말해야 함 |

Claude 의견: 구독 **구조**(요금제, 구독 상태, 만료 처리)를 보여주는 것이 핵심이므로 **B안**이 시간과 위험 면에서 낫다. A안은 시간이 남을 때 확장 후보로 둔다.

## 6. 기술 환경

### 6.1 Python 3.14 호환성 (노트북에 설치된 버전)
| 라이브러리 | 확인 결과 |
|---|---|
| SQLAlchemy | 2.0.44에서 3.14 설치 경로 수정됨 |
| psycopg2 | 2.9.11 변경 내역에 3.14 지원 추가 |
| uvicorn | 0.38.0에서 3.14 지원 추가 |
| FastAPI | 3.14 지원 명시를 찾지 못함 `[미확인]` |
| fsrs | `[미확인]` |

판단: 대부분 지원되는 것으로 보이나, **실제 설치 후 점검해야 확실하다.** 문제가 있으면 다른 Python 버전을 가상환경으로 쓰는 대안이 있다. 어느 경우든 패키지 설치는 대표 승인 후에 한다.

### 6.2 DB: PostgreSQL
- 공식 Windows 설치 파일은 EDB가 제공하며 서버, pgAdmin(관리 도구), StackBuilder가 함께 들어 있다.
- 설치하면 Windows 서비스(예: `postgresql-x64-18`)가 등록된다. 기본 설치 경로는 `C:\Program Files\PostgreSQL\18`. `[한 가이드 기준, 최신 버전 번호는 설치 전 공식 페이지에서 재확인]`
- 현황: 노트북에 미설치. 설치와 비밀번호 설정이 필요하다.

### 6.3 프론트엔드
- React 개발 도구(Vite 등)의 현재 권장 방식은 이번 조사에서 확인하지 못했다. 설계 단계에서 공식 문서로 확인한다. `[미확인]`

### 8.1 대표 결정 (2026-11-03)

| # | 항목 | 결정 | 비고 |
|---|---|---|---|
| 1 | 단어 데이터 방식 | **B**: TSL 목록을 뼈대로, 뜻·예문은 Claude가 작성 | 출처 표기 필요. 동일조건(SA) 영향은 상용 출시 전 확인(3.2) |
| 2 | 단어 규모 | **일부** (구체 개수는 요구사항 단계에서 확정) | 제안: 처음 약 500개로 품질 확인 |
| 3 | 복습 알고리즘 | **SM-2** (직접 구현) | 힌트 사용이 간격에 미치는 영향은 설계 단계 |
| 4 | 결제 시연 | **"진짜 결제 화면 연결"** (대표 표현) | 아래 주의 참고 |
| 5 | PostgreSQL | **지금 설치** | 17 버전, 설치 진행 중 |

**결제(4번) 주의**: 대표 표현 "진짜 결제 화면"을 토스페이먼츠 같은 실제 결제 위젯을 **테스트 키로 연결(실제 돈은 나가지 않음)** 하는 것으로 이해했다. 실제 돈이 오가는 결제는 사업자등록과 계약이 필요해 이번 범위(기획서 6.2)를 벗어난다. 이 이해가 맞는지 대표 확인이 필요하다. 또한 5장 A안의 불확실성(공식 문서 미확인, 정기결제 지원 여부)이 남아 있어, **요구사항 단계에서 공식 개발자 문서로 확인**하고 막히면 가짜 결제 화면(B안)으로 대체할 수 있도록 대비한다. 이로써 구독(결제)이 구현 6일 중 일정 위험이 큰 항목이 되었다.
