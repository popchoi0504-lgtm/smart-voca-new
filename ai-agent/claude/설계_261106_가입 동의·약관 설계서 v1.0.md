## 1. 배경과 목표

이메일·닉네임·학습 기록·결제 기록을 수집하는데 가입 화면에 동의 절차가 없다. 상용 서비스는 (1) 수집 전에 목적·항목·보유 기간을 알리고 동의를 받고, (2) 처리방침을 공개하고, (3) 누가 언제 어느 버전에 동의했는지 남겨야 한다(한국 개인정보 보호법 기준으로 알고 있는 내용이며 **법률 자문이 아니다**. 정식 출시 전 검수 필요).

이번에는 발표용으로 "동의 받기 + 기록 + 문서 페이지"의 뼈대를 만든다. 약관·방침 문구는 **초안**이다.

## 2. 요구사항 (요구사항 명세서 v1.1 에 반영할 항목)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-CONSENT-01 | 가입 화면에 필수 동의 3개(만 14세 이상, 이용약관, 개인정보 수집·이용)와 선택 동의 1개(마케팅 수신)를 체크박스로 보여 준다. 필수 중 하나라도 빠지면 가입할 수 없다(서버도 검사). | 필수 |
| FR-CONSENT-02 | 동의한 시각과 약관 버전을 회원 행에 기록한다. 마케팅 동의 여부도 기록한다. | 필수 |
| FR-CONSENT-03 | 이용약관(`/terms`)과 개인정보처리방침(`/privacy`)을 로그인 없이 볼 수 있다. 가입 화면과 화면 하단에서 링크로 연결한다. | 필수 |
| FR-CONSENT-04 | 설정에서 마케팅 수신 동의를 언제든 바꿀 수 있다(철회가 동의만큼 쉬워야 한다). | 필수 |
| NFR-CONSENT-01 | 화면에 보여 준 약관 버전과 서버의 현재 버전이 다르면 가입을 거부하고 새로고침을 안내한다(옛 문구에 동의한 기록이 남는 것을 막는다). | 필수 |
| NFR-CONSENT-02 | 문서에 "약관·방침 문구는 초안이며 정식 출시 전 법무 검수 필요"를 기록한다. | 필수 |

## 3. API (인터페이스 정의서 4.2·4.9 에 반영 예정)

**POST `/api/auth/signup`** 요청에 칸 추가(기존 `email`, `password` 는 그대로):

| 칸 | 규칙 |
|---|---|
| agree_age | 반드시 `true` (만 14세 이상) |
| agree_terms | 반드시 `true` (이용약관) |
| agree_privacy | 반드시 `true` (개인정보 수집·이용) |
| agree_marketing | 선택, 기본 `false` |
| terms_version | 화면에 보여 준 약관 버전 문자열. 서버의 현재 버전과 같아야 함 |

- 오류: 422 VALIDATION_ERROR(필수 칸이 `true` 가 아님, 칸 이름으로 표시), 409 `TERMS_VERSION_MISMATCH`(화면의 약관이 낡음)
- 성공 시 `terms_agreed_at`(서버 시각), `terms_version`, `marketing_agreed` 를 저장한다.

**PATCH `/api/me/consent`** — 로그인 필요 · FR-CONSENT-04
- 요청: `{ "marketing_agreed": true | false }`, 성공 200 `{ "user": {...} }`

공통 객체 `user` 에 `marketing_agreed`(불리언)를 추가한다. `terms_agreed_at` 은 화면에 필요 없어 내려 주지 않는다.

## 4. 데이터 변경 (데이터 설계서 4.1 에 반영 예정)

`users` 표에 칸 3개 추가(Alembic).

| 칸 | 타입 | 필수 | 설명 |
|---|---|---|---|
| terms_agreed_at | timestamptz | N | 필수 동의를 한 시각. 기존 회원(대표·데모 포함)은 비어 있음 |
| terms_version | text | N | 동의한 약관·방침 버전(예: `2026-11-06`) |
| marketing_agreed | boolean | Y | 마케팅 수신 동의, 기본 `false` (기존 회원은 `false` 로 채워짐) |

탈퇴 시 익명화 규칙에 추가: `terms_agreed_at`, `terms_version` 은 **남기고**(동의 증빙), `marketing_agreed` 는 `false` 로 바꾼다. 이메일이 지워지므로 개인을 특정할 수 없다. 이 처리를 `test_profile` 에 추가한다.

약관 버전 상수는 서버 `app/core_logic/consent_rules.py` 의 `TERMS_VERSION` 한 곳에 두고, 화면은 `GET /api/legal/version` 으로 받지 않고 **빌드된 상수**(`src/legal/version.js`)를 쓰되 두 값이 같은지 테스트로 확인한다(아래 AD-C3).

## 5. 약관·개인정보처리방침 페이지 (초안 내용)

화면은 로그인 없이 보이는 일반 페이지 2개. 문구는 `src/frontend/src/legal/` 에 JSX 로 둔다.

**개인정보처리방침에 들어갈 항목**

| 항목 | 내용 |
|---|---|
| 수집 항목 | 필수: 이메일, 비밀번호(복원할 수 없는 해시로만 저장). 이용 중 생성: 닉네임, 학습 기록, AI 선생님 사용 횟수, 결제 기록(주문번호·금액·상태·결제 키). 선택: 마케팅 수신 동의 여부 |
| 이용 목적 | 회원 식별·로그인, 학습 기능 제공, 결제 처리, (동의 시) 서비스 소식 안내 |
| 보유 기간 | 회원 탈퇴 시 학습 기록·AI 사용 횟수는 즉시 삭제, 개인정보는 익명화. 결제 기록은 법정 보관 기간 동안 익명화한 채 보관(**기간은 정식 출시 전 확인 필요**) |
| 처리 위탁·국외 이전 | 결제: 토스페이먼츠. AI 선생님: Google(Gemini)에 단어와 질문 글만 전송(이메일·학습 기록은 보내지 않음), 국외 이전 해당 여부는 **정식 출시 전 확인 필요** |
| 이용자 권리 | 열람·수정: 설정, 삭제: 회원 탈퇴, 마케팅 철회: 설정 |
| 안전 조치 | 비밀번호 Argon2 해시, 로그인 쿠키 HttpOnly, 로그에 비밀번호·이메일 원문 미기록 |
| 쿠키 | 로그인 유지용 쿠키 1개만 사용(광고·추적 쿠키 없음) |
| 문의처·책임자 | `<미정>` (팀 확정 후 기입) |

**이용약관 초안 항목**: 서비스 소개, 만 14세 이상 가입, 계정 관리 책임, 이용권 결제·환불(**정책 미정, 정식 출시 전 확정**), AI 설명이 틀릴 수 있음, 금지 행위, 단어 목록 출처 표기(CC BY-SA 4.0, 기존 SourceNotice 유지), 약관 변경 고지.

## 6. 화면

- `SignupPage`: 이메일·비밀번호 아래 "전체 동의" 체크(편의 기능) + 항목 4개(필수 3·선택 1), 각 항목 옆 "보기" 링크(새 탭으로 `/terms`·`/privacy`). 필수 미체크 시 가입 버튼 비활성.

- 설정: "알림" 구역에 마케팅 수신 토글(저장 시 PATCH).

## 7. 결정 기록 (ADR)

| ID | 결정 | 대안 | 이유 |
|---|---|---|---|
| AD-C1 | 필수 3개를 **한 시각·한 버전**으로 기록 | 항목마다 별도 표(`consents`)에 기록 | 이번 필수 항목은 항상 함께 동의한다. 항목별 버전이 갈라지면 그때 표를 만든다 |
| AD-C2 | 만 14세 이상 확인을 필수 체크로 | 약관 문구로만 명시 | 법정대리인 동의 절차를 만들지 않으려면 가입 시점에 명시적으로 확인하는 편이 안전하다 |
| AD-C3 | 화면이 보여 준 버전을 보내고 서버가 대조 | 서버가 현재 버전을 마음대로 기록 | 낡은 화면에서 동의해도 최신 버전에 동의한 것으로 남는 오류를 막는다. 상수가 두 곳이라 같은지 테스트로 지킨다 |
| AD-C4 | 서버도 필수 동의를 검사 | 화면 검사만 | 화면은 우회할 수 있다 |
| AD-C5 | 마케팅은 선택, 설정에서 변경 가능 | 마케팅 항목 생략 | 지금 마케팅 발송 기능은 없지만 나중에 쓰려면 가입 때 받아 두어야 한다. 쓰지 않으면 항목을 빼도 된다(대표 결정) |
| AD-C6 | 기존 회원은 동의 기록 없음으로 둠 | 다음 로그인 때 재동의 모달 | 재동의 모달은 범위가 커서 정식 출시 전 과제로 둔다. 기존 회원은 개발용 계정뿐이다 |
| AD-C7 | 탈퇴 후에도 동의 시각·버전은 남김 | 함께 삭제 | 개인을 식별할 수 없는 증빙이고, 동의 사실 증명에 필요하다 |

## 8. 테스트 계획 (`tests/test_consent.py`)

- 가입: 필수 3개가 모두 `true` 이면 201이고 `terms_agreed_at`·`terms_version`·`marketing_agreed` 가 저장된다. 하나라도 빠지거나 `false` 이면 422(칸 이름 확인)이고 회원이 만들어지지 않는다.
- 버전: 틀린 `terms_version` → 409 `TERMS_VERSION_MISMATCH`, 회원 미생성.
- 마케팅: 안 보내면 `false`, `true` 로 보내면 저장, 설정 변경 PATCH 로 바뀌고 로그인 없으면 401.
- 탈퇴: 동의 시각·버전은 남고 `marketing_agreed` 는 `false`.
- 서버·화면 약관 버전 상수가 같다(파일 내용 비교).
- 로그: 가입·동의 변경 로그에 이메일 원문이 없다.
- 기존 가입 테스트 전체(여러 파일의 `signup` 호출)에 동의 칸을 넣도록 고친다. 공통 도우미 `tests/conftest.py` 에 `SIGNUP_CONSENT` 상수를 두고 각 호출에 합친다.
- 일부러 고장 내기: 서버 필수 동의 검사 제거, 버전 대조 제거, 동의 시각 미기록, 탈퇴 시 마케팅 동의 미해제, 로그에 이메일 → 테스트가 잡는지 확인.

## 9. 진행 순서

1. (이 문서) 대표 확인 → 2. 규칙·스키마·서비스 + 단위 테스트, 기존 가입 테스트 수정 → 3. Alembic 변경 파일 생성·설계서 대조, **개발 DB 적용 전 대표 승인** → 4. 라우터·통합 테스트 → 5. 화면(가입 체크박스, `/terms`, `/privacy`, 하단 링크, 설정 토글) → 6. 확인(임시 계정, 375폭) → 7. 문서·일지·질문 모음·시드 스크립트(`seed_demo.py` 가 만드는 계정에 동의 기록) 갱신.
