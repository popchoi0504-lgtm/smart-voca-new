## 1. 배경과 목표

지금 설정 화면에는 "하루 새 단어 수"뿐이다. 홈 인사에 이메일이 그대로 보이고, 비밀번호를 바꾸거나 탈퇴할 방법이 없다. 상용 서비스라면 최소한 갖춰야 할 기능이라(질문 모음 Q69 ②) 이번에 채운다. 기존 코드를 최대한 재사용하고, 새 표는 만들지 않고 `users` 표에 칸만 추가한다.

## 3. API (인터페이스 정의서 4.9 로 추가 예정)

모두 로그인 필요. 로그인 안 했으면 401 `NOT_AUTHENTICATED`.

| 메서드·주소 | 요청 | 성공 | 오류 |
|---|---|---|---|
| `PATCH /api/me/profile` | `{ "nickname"?: "...", "avatar_color"?: "mint" }` (보낸 칸만 바꾼다) | 200 `{ "user": {...} }` | 422 (닉네임 길이·허용 안 되는 색) |
| `POST /api/me/password` | `{ "current_password", "new_password" }` | 204 + 새 로그인 쿠키(이 기기만 새로 발급) | 400 `WRONG_PASSWORD`, 422 (새 비밀번호 규칙·현재와 같음) |
| `GET /api/me/plan` | 없음 | 200 `{ "plan", "premium_until", "ai_daily_limit", "ai_used_today", "ai_remaining_today" }` | 401 |
| `POST /api/me/withdraw` | `{ "password", "confirm_text": "탈퇴합니다" }` | 204 + 쿠키 삭제 | 400 `WRONG_PASSWORD`, 422 (확인 문구 불일치) |

공통 객체 `user` 에 추가하는 칸(기존 칸은 그대로):

| 칸 | 설명 |
|---|---|
| nickname | 정한 닉네임, 없으면 null |
| display_name | 닉네임, 없으면 이메일의 @ 앞부분. 화면은 이 값만 쓴다 |
| avatar_color | 실제로 쓰는 색 이름. 고른 값이 없으면 이메일로 자동 배정한 값 |

색 6종: `mint`, `lavender`, `yellow`, `pink`, `sky`, `orange` (화면 색값은 CSS 에서 정한다).

## 4. 데이터 변경 (데이터 설계서 4.1 에 반영 예정)

`users` 표에 칸 3개 추가. Alembic 으로 적용하고, 기존 회원은 모두 비어 있는 상태(null)로 시작한다.

| 칸 | 타입 | 필수 | 설명 |
|---|---|---|---|
| nickname | text | N | 2~12자. 길이는 서버가 검사(중복 허용이라 UNIQUE 없음) |
| avatar_color | text | N | 6종 중 하나. DB 제약 `ck_users_avatar_color_allowed` 로 잘못된 값을 막는다 |
| deleted_at | timestamptz | N | 탈퇴한 시각. 값이 있으면 탈퇴한 회원 |

**주의: `deleted_at` 은 대표 요구에 없던 추가 칸이다.** 이유는 5.2 의 "탈퇴 뒤에도 쓸 수 있는 옛 로그인 쿠키" 문제 때문이다. 승인하지 않으면 이메일이 `@deleted.invalid` 로 끝나는지로 판별하는 대안이 있으나 약속(관례)에 기대는 방식이라 권하지 않는다.

## 5. 회원 탈퇴 규칙

### 5.1 한 번의 거래(트랜잭션)로 처리하는 순서

비밀번호 확인과 확인 문구 검사를 통과하면, 아래를 **전부 성공하거나 전부 취소**되게 한다.

1. `user_words`, `review_logs`, `ai_usages` 에서 이 회원의 행을 지운다(학습 기록·AI 사용 횟수).
2. `users` 행을 익명화한다.
   - `email` → `deleted-{회원번호}@deleted.invalid` (UNIQUE 를 지키려고 회원마다 다르게. `.invalid` 는 실제로 존재할 수 없는 주소)
   - `password_hash` → 해시가 아닌 고정 문자열 `!` (어떤 비밀번호로도 로그인 불가)
   - `nickname`, `avatar_color` → null, `premium_until` → null, `deleted_at` → 지금
3. `payments` 는 건드리지 않는다. `payments.user_id` 는 삭제 규칙이 없어 회원 행을 지울 수 없으므로 익명화한 행에 계속 연결된다.
4. 로그인 쿠키를 지운다.

결제 기록에는 주문번호·금액·상태·결제 키만 있고 이름·이메일은 없다. 익명화한 회원 행과 연결되므로 "누구의 결제인지"는 알 수 없고, 세무·분쟁 대응용 기록만 남는다.

### 5.2 옛 로그인 쿠키 문제와 대응

회원 행은 남아 있으므로, 탈퇴 전에 발급된 로그인 쿠키(최대 7일 유효)를 다른 기기가 갖고 있으면 `get_current_user` 가 "회원이 있다"고 통과시킨다. 그래서 `deleted_at` 이 있는 회원은 401 로 막는다.

### 5.3 재가입

탈퇴하면 원래 이메일이 `users` 에서 사라지므로 같은 이메일로 새 회원 행을 만들 수 있다. 새 회원은 새 번호를 받아 옛 기록과 이어지지 않는다.

### 5.4 확인 문구와 안내

화면에 "탈퇴하면 학습 기록이 모두 지워지고 되돌릴 수 없어요. 이용권이 남아 있어도 사라지고, 환불 규정은 정식 출시 전에 정해요."를 보여 준다. 확인 문구는 `탈퇴합니다` 를 그대로 입력해야 버튼이 켜진다(서버도 한 번 더 검사).

## 6. 비밀번호 변경의 한계 (기록)

- 로그인 쿠키(JWT)는 **서버가 목록으로 관리하지 않아** 비밀번호를 바꿔도 이미 발급된 쿠키는 만료(7일)까지 유효하다. 다른 기기에서 훔친 쿠키가 있다면 7일간 쓸 수 있다.
- 해결책은 회원 행에 "토큰 버전" 칸을 두고 비밀번호를 바꿀 때 올리는 것인데 **이번 범위 밖**이다. 정식 출시 전 과제로 둔다.
- 현재 비밀번호를 틀리게 반복 입력하는 시도를 막는 장치(횟수 제한)는 로그인과 마찬가지로 아직 없다. 같은 과제에 묶는다.

## 7. 결정 기록 (ADR)

| ID | 결정 | 대안 | 이유 |
|---|---|---|---|
| AD-P1 | 탈퇴는 **익명화**(회원 행 유지) | 완전 삭제 | 결제 기록을 법정 기간 보관해야 하고, `payments.user_id` 에 삭제 규칙이 없어 회원 행을 지우면 막힌다 |
| AD-P2 | 학습 기록은 **삭제** | 익명 통계로 보관 | 개인정보 최소화. 팀이 쓸 통계 요구가 아직 없다 |
| AD-P3 | 아바타는 **이니셜 + 색 6종** | 사진 업로드 | 파일 저장·검수·용량·저작권 부담이 없고 구현이 작다 |
| AD-P4 | 색이 없으면 이메일 글자 합계로 **자동 배정** | 항상 같은 색 | 사람마다 다른 색이라 보기 좋고, 저장 없이 계산만 하면 된다 |
| AD-P5 | 닉네임 중복 허용 | 중복 금지 | 로그인 ID 는 이메일이라 닉네임은 보기용일 뿐이다. 중복 검사는 동시 가입 경합·사용성 부담이 크다 |
| AD-P6 | `display_name` 을 서버가 계산해 내려 줌 | 화면마다 닉네임/이메일 중 고르기 | 규칙이 한 곳에 모이고 화면은 이 값만 쓰면 된다 |
| AD-P7 | 비밀번호 변경 시 **현재 기기만 새 쿠키** 발급 | 모든 기기 로그아웃 | 모든 기기 로그아웃은 토큰 버전이 필요(범위 밖). 6장에 한계 기록 |
| AD-P8 | 탈퇴·변경 API 는 `POST /api/me/...` 동작 이름 방식 | `DELETE /api/me` | 삭제 요청에 본문(비밀번호)을 싣는 것은 일부 도구가 버려서 불안정. 기존 `/api/me/settings` 와 같은 줄에 둠 |
| AD-P9 | `deleted_at` 칸 추가 | 이메일 접미사로 판별 | 5.2 참고. 명시적 칸이 실수에 강하다 |

## 8. 테스트 계획 (자동 테스트, 파일 `tests/test_profile.py`)

- 닉네임: 2~12자 통과, 1자·13자·공백만·줄바꿈 포함 거부, 앞뒤 공백 정리, 중복 허용, 미로그인 401.
- 아바타: 6색 통과, 목록 밖 색 거부, 색 없을 때 자동 배정이 같은 이메일에 항상 같은 값.
- `display_name`: 닉네임 있을 때/없을 때(이메일 @ 앞부분).
- 비밀번호 변경: 성공 후 새 비밀번호로 로그인되고 옛 비밀번호는 거부, 현재 비밀번호 틀림 400, 새 비밀번호 규칙 위반 422, 현재와 같은 값 422.
- 이용권 요약: 무료/프리미엄, AI 사용 횟수 반영.
- 탈퇴: 비밀번호 틀림·확인 문구 틀림 시 아무것도 안 바뀜, 성공 시 학습 기록·AI 횟수 삭제, 결제 기록 유지, 이메일·해시·닉네임 익명화, 탈퇴 전 쿠키 401, 같은 이메일로 재가입 가능, 다른 회원 기록은 영향 없음.
- 로그: 비밀번호·이메일 원문·새 비밀번호가 로그 전체에 없다(`test_log_safety` 방식).
- 일부러 고장 내기: 현재 비밀번호 확인 제거, 탈퇴 시 결제 삭제, 학습 기록 삭제 누락, `deleted_at` 검사 제거, 로그에 이메일 출력 → 테스트가 잡는지 확인.

## 9. 화면

`SettingsPage` 를 기존 카드 스타일의 구역 5개로 나눈다: ① 프로필(닉네임·색 선택·미리보기) ② 이용권 요약 ③ 학습(기존 하루 새 단어 수) ④ 보안(비밀번호 변경) ⑤ 위험 구역(탈퇴). 이니셜 아바타 컴포넌트(`Avatar.jsx`)는 상단 메뉴와 홈 인사, 설정에서 같이 쓴다. 출처 표기(SourceNotice)는 유지한다.
