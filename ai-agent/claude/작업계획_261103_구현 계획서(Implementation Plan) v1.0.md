## 2. 슬라이스(VS) 정의

슬라이스 하나는 "끝까지 동작하는 기능 묶음"이다. 위에서 아래로 의존한다.

| VS | 이름 | 만드는 것 | 요구사항 | API | 추정 |
|---|---|---|---|---|---|
| VS-0 | 뼈대(걷는 해골) | 서버·화면·DB 가 이어져 `/health` 가 화면에 보임. 설정·로그·오류 처리 틀 | FR-SYS-01~03 | health | 3h |
| VS-1 | 계정 | 회원가입·로그인·로그아웃, 보호된 화면 | FR-AUTH-01~07 | auth/*, me/settings 제외 | 6h |
| VS-2 | 단어 데이터 | 단어 500개 작성·검수·적재 | FR-WORD-01~06 | (조회용 내부) | 4h (+작성) |
| VS-3 | 새 단어 학습 + SM-2 | 오늘 할 것, 플래시카드, SM-2 첫 계산, 설정 | FR-STUDY-01~06, FR-SRS-01~03·06 | study/*, me/settings | 6h |
| VS-4 | 퀴즈 + 힌트 | 복습 퀴즈, 3단계 힌트, 연습 규칙 | FR-QUIZ-01~03, FR-HINT-01~06, FR-SRS-04~05 | quiz/* | 7h |
| VS-5 | 구독·결제 | 요금제 범위, 결제위젯(또는 가짜), 이용권, 결제 내역 | FR-SUB-01~08 | subscription, payments/* | 6h |
| VS-6 | 학습 기록 | 연속 학습일, 숙련도, 진행 시각화 | FR-PROG-01~05 | progress/summary | 4h |
| VS-7 | 마감 | 오류·로그 점검, 전체 테스트, 실행·백업 문서, 화면 다듬기 | FR-SYS-04~05, NFR 전체 | - | 5h |
| 합계 | | | | | 약 41h |

**순서를 이렇게 한 이유**
- VS-0 을 맨 앞에 둔 것: 가장 작은 기능(서버 상태 확인)을 화면 → 서버 → DB 까지 먼저 이어 보면, 환경 문제(Python 3.14 호환, 포트, 프록시)를 **일찍** 발견한다.
- VS-5(결제)를 VS-6(기록)보다 앞에 둔 것: 결제는 외부 서비스 연동이라 **가장 불확실**하다. 위험이 큰 것을 일찍 하면 막혔을 때 대체(가짜 결제)로 갈 시간이 남는다. 기록 화면은 위험이 낮아 뒤로 미뤄도 된다.
- VS-2(단어 데이터)를 VS-3 앞에 둔 것: 학습 화면을 만들려면 단어가 있어야 한다.

## 3. 슬라이스 하나를 만드는 순서 (모든 VS 공통)

1. **개념 설명** (5~10분): 이번에 만드는 것이 무엇인지, 왜 그렇게 하는지, 대안은 무엇이었는지를 쉬운 말로 설명한다. (CLAUDE.md 설명 의무)
2. **표**: 필요한 표를 Alembic 변경 파일로 만든다 (데이터 설계서 기준).
3. **핵심 로직 + 단위 테스트**: DB 없이 도는 순수 계산부터 (`core_logic/`).
4. **서비스·라우터 + 통합 테스트**: 인터페이스 정의서의 모양 그대로.
5. **화면**: 해당 페이지와 API 호출 코드.
6. **직접 확인**: 브라우저에서 시나리오를 실제로 눌러 본다. 테스트 통과만으로 끝내지 않는다.
7. **이해 확인**: Claude 가 질문 3개를 던지고, 대표가 자기 말로 답한다. 막히면 해당 부분을 다시 설명한다.
8. **문서·기록**: 설계 문서에서 달라진 점 갱신, 일지 기록, 발표 Q&A 추가.
9. **커밋**: 슬라이스 완료 시 대표에게 커밋·푸시 승인을 요청한다.

코드 규칙: 파일은 하나씩 만들고 200줄이 넘으면 나눠서 진행, 500줄이 넘으면 분리를 제안, 모든 파일에 헤더(작성일·위치·목적), 의미 있는 이름. (CLAUDE.md)

## 4. 슬라이스별 상세

### VS-0 뼈대 (3h)
- 만드는 것: 가상환경과 서버 패키지 설치, `src/backend/app/main.py` 와 `core/config.py`(설정), `core/logging.py`, `core/errors.py`(공통 오류 모양), `routers/health.py`. `src/frontend` 를 Vite 로 생성하고 `vite.config.js` 에 `/api` 프록시, 첫 화면에서 `/api/health` 호출. 서비스 전용 DB `smart_voca`(와 테스트용 `smart_voca_test`), 전용 DB 사용자 생성. `.env.example` 작성. Alembic 초기화.
- 완료 기준: 브라우저(5173)에서 "서버 ok / DB ok" 표시. DB 를 끄면 503 응답과 화면 안내. 로그 파일에 요청 기록. 실행 명령 2개가 정리됨.
- 확인할 호환성: Python 3.14 에서 모든 서버 패키지가 설치되는가, 안 되면 다른 Python 버전 가상환경 `[아키텍처 14장 #3, #4]`
- 이해 확인 예: "화면에서 `/api/health` 를 부르면 어떤 순서로 DB 까지 가나요?"

### VS-1 계정 (6h)
- 표: `users`. 핵심 로직: 비밀번호 해시·검증, 토큰 발급·검증 (`core/security.py`). API: signup, login, logout, me. 화면: 가입, 로그인, 로그인 안 하면 이동 처리(보호 라우트).
- 테스트: 가입 중복 거부, 로그인 성공·실패, 비밀번호가 DB 에 원문으로 없음, 쿠키 없이 보호 API 호출 시 401, 비밀번호 규칙 위반 시 422.
- 완료 기준: 새 이메일로 가입 → 자동 로그인 → 새로고침해도 유지 → 로그아웃 → 보호 화면 접근 불가.
- 이해 확인 예: "비밀번호를 왜 해시로 저장하나요? 쿠키를 HttpOnly 로 한 이유는?"

### VS-2 단어 데이터 (4h + 작성 시간)
- 표: `words`. 데이터: `data/words/toeic_500.csv` (영단어, 품사, 뜻, 예문, 예문 번역, 빈도 순서). 도구: `ai-agent/scripts/seed_words.py`(여러 번 실행해도 중복 없음, 예문에 영단어가 그대로 있는지·중복·빈 칸 검사).
- 작성 방법: TSL 단어 목록을 기준으로 상위 500개를 고르고, 뜻·예문은 Claude 가 100개씩 5번에 나눠 작성한다. 대표가 각 묶음에서 샘플 약 10개를 검수한다. TSL 목록 파일은 출처 사이트에서 내려받아야 하며(**외부 다운로드, 승인 필요**), 파일 형식과 라이선스 문구는 받을 때 확인한다 `[구현 시 확인]`. 내려받지 못하면 Claude 가 빈출 단어를 직접 골라 TSL 과 대조 가능한 부분만 대조하고, 한계를 문서에 적는다.
- 출처 표기(FR-WORD-04): `data/words/` 에 안내 파일, 화면 하단 문구. CC BY-SA 동일조건 영향은 상용 출시 전 확인 항목으로 문서화(환경 분석서 3.2).
- 완료 기준: 시드 실행 후 `words` 500행, 다시 실행해도 500행, 검사 스크립트 통과, 대표 샘플 검수 통과.
- 이해 확인 예: "왜 단어 목록은 공개 자료에서, 뜻과 예문은 직접 썼나요?"

### VS-3 새 단어 학습 + SM-2 (6h)
- 표: `user_words`, `review_logs`. 핵심 로직: `core_logic/sm2.py`(간격 계산), `core_logic/quality.py`(결과→점수). API: study/today, study/new, study/flashcard, me/settings. 화면: 오늘 할 것(Today), 플래시카드(Flashcard), 설정(Settings).
- 테스트(단위): SM-2 의 첫 복습 1일, 두 번째 6일, 이후 간격 증가, 점수가 낮으면 처음부터, 난이도 계수 하한 1.30. 통합: 요금제 범위(250 초과 새 단어 거부), 같은 카드 두 번 평가 시 409.
- 완료 기준: 새 단어 10개를 평가하면 `user_words`·`review_logs` 에 반영되고, 다음 날 복습 대상으로 잡힌다(시간 이동은 테스트에서 날짜를 바꿔 검증). 설정에서 하루 새 단어 수를 바꾸면 오늘 할 것에 반영.
- 이해 확인 예: "SM-2 에서 '알았음'을 누르면 다음 복습일이 왜 늘어나나요?"

### VS-4 퀴즈 + 힌트 (7h)
- 핵심 로직: `core_logic/hints.py`(섞기, 빈칸, 예외 처리, 날짜·회원 고정). API: quiz/queue, hint, answer(연습 규칙 IF-4 포함). 화면: Quiz, HintPanel.
- 테스트(단위, 가장 두껍게): 섞은 결과가 원형과 다름, 3글자 이하·같은 글자만인 단어는 건너뜀, 공백·하이픈 고정, 같은 날 같은 결과(결정적), 빈칸 공개 글자가 정답의 같은 위치 글자, 첫 글자 공개. 통합: 문제 목록에 정답 영단어가 없음, 오답 시 정답 미공개, 정답 확인은 `revealed` 로 별도 기록, 같은 단어 두 번째 제출은 연습.
- 완료 기준: 복습 대상 퀴즈를 풀고 → 힌트 1·2·3단계를 열어 보고 → 결과가 `review_logs` 에 `max_hint_level` 과 함께 남고 → 다음 복습일이 바뀐다.
- 이해 확인 예: "정답을 왜 브라우저에 보내지 않나요? 힌트를 매번 같게 한 이유는?"

### VS-5 구독·결제 (6h)
- 표: `payments`. `payments/provider.py`(공통 모양), `toss_provider.py`, `fake_provider.py`. API: subscription, payments/orders, confirm, 내역. 화면: Subscribe, 결제 성공·실패 페이지. 요금제 범위는 VS-3 에서 이미 막고 있으므로, 이용권이 있으면 열리는지 통합 테스트로 확인.
- **대표가 직접 할 일**: 토스페이먼츠 개발자센터 회원가입 후 테스트 키(결제위젯용 `test_gck_`/`test_gsk_` 세트) 확인·`.env` 입력. 키를 대화창에 붙여넣지 말고 `.env` 에 직접 입력한다. 11-06 까지 필요 `[대표 일정]`
- 테스트: 결제 사 응답을 가짜로 대체한 상태에서 성공·실패·금액 불일치·중복 확인(이용권이 한 번만 연장), 이용권 만료 후 새 단어 범위 복귀.
- 완료 기준: 구매 버튼 → 결제위젯(테스트) → 성공 → 이용권 만료일 표시 → 프리미엄 단어 학습 가능. 연동이 막히면 가짜 결제로 같은 흐름이 동작(FR-SUB-08).
- 이해 확인 예: "결제 금액을 왜 서버가 정하나요? 같은 확인을 두 번 보내면?"

### VS-6 학습 기록 (4h)
- API: progress/summary(연속 학습일 계산, 숙련도 분포). 화면: Progress(오늘 학습량, 연속 학습일, 숙련도, 진행 바).
- 테스트: 연속 학습일 경계(오늘 학습 전, 하루 건너뜀, 자정 전후), 숙련도 구간.
- 완료 기준: 지금까지의 학습이 숫자·시각 요소로 정확히 보인다.

### VS-7 마감 (5h)
- 오류 메시지와 로그 점검(비밀번호·토큰이 로그에 없는지), 전체 테스트 실행, 실행 문서와 백업·복원 문서(`운영_…`), 빈 화면·로딩·오류 상태 처리, 팀원 시연용 데이터(데모 계정과 학습 이력) 준비, 시스템명 반영.
- 완료 기준: 처음 보는 사람이 문서만 보고 실행할 수 있고, 시연 시나리오 1회를 막힘없이 통과.

## 6. 지연 대응 (범위는 줄이지 않는다, D-6)

기능을 빼는 대신, **같은 기능을 더 단순한 방법으로 구현**하는 대체안을 미리 정한다. 아래 조건이 되면 대표에게 알리고 바로 적용한다.

| 발동 조건 | 대체안 | 잃는 것 |
|---|---|---|
| 11-08 밤까지 토스 위젯 연동이 안 됨 | 가짜 결제(FR-SUB-08)로 같은 흐름 구현 | 실제 결제창 모양 |
| Alembic 에서 이틀 이상 막힘 | `create_all` 로 표 생성 | 표 변경 이력 |
| Argon2 설치 실패 | bcrypt 사용 (AD-3) | 권장 방식 우선순위 |
| Python 3.14 비호환 라이브러리 | 다른 Python 버전의 가상환경 | 설치 부담 |
| VS 하나가 계획보다 2h 이상 지연 | 다음 날 슬라이스 시작 전 대표와 재계획 | - |
| 11-08 밤 기준 VS-5 미완 | 11-09 의 VS-6·VS-7 시간을 VS-5 로 돌리고, VS-6 은 기본 지표만 먼저(연속 학습일·숙련도 수치), 시각 요소는 11-11 에 | 기록 화면 완성도 |

밤샘 전 경고: 밤샘은 판단력과 이해 시간을 줄여 **발표에서 설명이 막힐 위험**이 커진다. 밤샘이 필요해지면 그 시간에는 새 기능 구현 대신 테스트 실행처럼 이해를 덜 요구하는 일을 하는 것을 권한다. 이 판단은 대표의 몫이다.

## 11. 개발 허가 요청

아래 범위의 허가를 요청한다. 허가는 **범위 단위**로 주면 된다.

1. **코드 작성**: `src/`, `ai-agent/scripts/`, `data/words/` 아래 파일 생성·수정
2. **패키지 설치**: 7장의 서버·화면 패키지 (설치 시 버전 확인)
3. **DB 작업**: 전용 DB·사용자 생성, 표 생성(Alembic), 시드 데이터 적재
4. **외부 다운로드**: TSL 단어 목록 1건
5. **커밋·푸시**: 슬라이스 완료마다 승인 요청 (자동 커밋은 하지 않음)

허가해도 그대로 유지되는 것: 설명 의무, 슬라이스마다 이해 확인, `.env`·키는 대화창에 붙여넣지 않기, 승인이 필요한 항목(위 외 설치·삭제·외부 호출)은 그때그때 확인.
