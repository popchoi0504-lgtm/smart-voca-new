# 프로세스 설계서 (Process Logic)

**파일 위치**: `docs/설계_261118_프로세스 설계서(Process Logic) v1.0.md`
**작성일**: 2026-11-18
**버전**: v1.0 (초안, 대표 검토 전)
**설명**: 복습 계산(SM-2), 힌트, 퀴즈·학습 처리, 연속 학습일, 결제 확인·환불의 규칙을 단계별로 적는다. 화면이 아니라 "서버가 무엇을 어떤 순서로 계산하고 저장하는가"를 설명한다.

## 1. 용어 풀이

- **SM-2**: 기억 곡선을 이용해 "다음에 언제 복습할지"를 정하는 오래된 공식. 잘 기억하면 간격이 점점 길어지고, 틀리면 다시 짧아진다.
- **점수(quality, 0~5)**: 학습 결과를 SM-2가 이해하는 숫자로 바꾼 값. 3 이상이면 "기억함", 2 이하면 "기억 못 함"으로 본다.
- **난이도 계수(ease factor, 줄여서 EF)**: 단어마다 가진 "쉬운 정도". 처음 값 2.50, 최솟값 1.30.
- **연속 성공 횟수(repetitions)**: 연속으로 기억했다고 답한 횟수.
- **복습 간격(interval_days)**: 다음 복습까지 며칠 뒤인지.
- **KST**: 한국 표준시. 날짜 경계(자정)는 모두 KST로 계산한다.

## 2. 복습 계산 (SM-2) — `core_logic/sm2.py`

### 2.1 입력과 출력
- 입력: 현재 상태(연속 성공 횟수, 간격, EF)와 점수(0~5)
- 출력: 새 상태. **원래 상태 값은 바꾸지 않고 새 값을 돌려준다.**
- 점수가 0~5 밖이면 오류.

### 2.2 규칙
| 상황 | 연속 성공 횟수 | 간격 | EF |
|------|---------------|------|----|
| 점수 3 미만 (실패) | 0으로 되돌림 | 1일 | 그대로 |
| 점수 3 이상, 1번째 성공 | 1 | 1일 | 바뀜 |
| 점수 3 이상, 2번째 성공 | 2 | 6일 | 바뀜 |
| 점수 3 이상, 3번째부터 | +1 | 이전 간격 × EF (반올림) | 바뀜 |

**EF 조정 공식**: 새 EF = EF + (0.1 − (5 − 점수) × (0.08 + (5 − 점수) × 0.02)), 1.30 아래로는 내려가지 않는다.
- 점수 5: EF +0.10
- 점수 4: EF 그대로
- 점수 3: EF −0.14

**왜 실패해도 EF를 안 낮추나**: SM-2 원래 규칙을 따랐다. 실패의 벌은 간격을 1일로 되돌리는 것으로 충분하다고 보았다. 대안(실패 시 EF도 낮춤)은 단어가 계속 어려운 것으로 굳어질 수 있어 채택하지 않았다.

### 2.3 계산 예시 (단어 1개, 처음부터 5점을 3번 받는 경우)
1. 처음 학습 → 점수 5 → 연속 1, 간격 1일, EF 2.60
2. 다음 복습 → 점수 5 → 연속 2, 간격 6일, EF 2.70
3. 다음 복습 → 점수 5 → 연속 3, 간격 round(6 × 2.70) = 16일, EF 2.80
4. 다음 복습 → 점수 1 (틀림) → 연속 0, 간격 1일, EF 2.80 (그대로)

## 3. 점수 변환 — `core_logic/quality.py`

### 3.1 플래시카드(새 단어 학습 직후 자기 평가)
| 학습자 선택 | 점수 | 뜻 |
|-------------|------|-----|
| 몰랐음 (`dont_know`) | 1 | 실패 |
| 애매함 (`unsure`) | 3 | 간신히 성공 |
| 알았음 (`know`) | 5 | 완벽 |

### 3.2 퀴즈 (영단어 직접 입력)
| 결과 | 사용한 최고 힌트 단계 | 점수 | 뜻 |
|------|----------------------|------|-----|
| 정답 (correct) | 없음(0) | 5 | 힌트 없이 맞힘 |
| 정답 | 1단계(철자 섞기) | 4 | |
| 정답 | 2단계(빈칸) | 3 | |
| 정답 확인 (revealed) | 3단계 | 2 | 오답보다 덜 감점하되 복습은 앞당김 |
| 오답 (wrong) | — | 1 | 실패 |

**왜 정답 확인을 오답(1)과 나눴나**: 답을 본 것은 틀린 것과 다르다고 보았다. 점수 2는 "기억 못 함"으로 간주하지만 1보다는 덜 벌한다. 이 값은 요구사항 D-5 결정이며 구현 후에도 표 한 곳만 고치면 된다.

## 4. 힌트 — `core_logic/hints.py`

### 4.1 공통 규칙
- **고정 난수(seed)**: 회원 번호, 단어 번호, 날짜, 힌트 단계를 합해 sha256으로 숫자를 만든다. 같은 입력이면 항상 같은 힌트가 나온다.
- **왜 이렇게 했나**: 새로고침할 때마다 힌트가 바뀌면 학습자가 혼란스럽다. 날짜가 바뀌면 다른 모양이 나오도록 날짜를 넣었다. 파이썬 기본 `hash()`는 실행할 때마다 값이 달라서 쓰지 않는다.
- **공백·하이픈**: 섞거나 가리지 않고 제자리에 둔다.

### 4.2 1단계: 철자 섞기
1. 글자 수(공백·하이픈 제외)가 4개 미만이면 건너뛴다(`skipped = true`).
2. 서로 다른 글자가 한 종류뿐이면(예: `aa`) 건너뛴다.
3. 글자를 무작위로 섞는다. 원래 단어와 같으면 다시 섞는다.

### 4.3 2단계: 빈칸
1. 공개할 글자 수 = 글자 수 × 0.4, 반올림, 최소 1, 최대 (글자 수 − 1). 한 칸은 반드시 가린다.
2. 첫 글자는 항상 공개한다.
3. 나머지 공개 칸은 고정 난수로 고른다.
4. 공개된 글자는 정답의 **같은 위치** 글자다. 가린 칸은 `_`로 표시한다.

예: `apple`(5글자)은 공개 2칸. 첫 글자 `a`와 2번째 글자 `p`를 공개하면 `a p _ _ _`.

### 4.4 3단계: 정답 확인
정답 단어 전체를 보여준다. 이때 해당 문제는 **오답이 아니라 `revealed`로 따로 기록**한다.

## 5. 퀴즈 답 제출 — `services/quiz_service.py: submit_answer`

1. 단어가 없으면 404. 배운 단어가 아니면 409(`WORD_NOT_LEARNED`).
2. 판정:
   - 힌트 3단계를 봤으면 입력과 상관없이 `revealed`.
   - 아니면 대소문자와 앞뒤 공백을 무시하고 비교해 `correct` 또는 `wrong`.
   - 오답이면 정답은 응답에 넣지 않는다.
3. **오늘 첫 제출인지 확인** (아래 중 하나라도 해당하면 "연습"):
   - 오늘 이미 퀴즈 기록이 있음
   - 다음 복습일이 아직 오늘 이후임 (새로 배운 직후 등)
   - 연습이면 판정 결과만 돌려주고 **일정과 기록은 바꾸지 않는다.** (응답의 `practice = true`)
4. 첫 제출이면:
   - 같은 단어를 동시에 두 번 보내도 한 번만 반영되도록 단어 행을 잠근다(`FOR UPDATE`).
   - 점수 계산 → SM-2 계산 → 단어 상태 갱신 → 다음 복습일 = 오늘 + 간격 → 기록 추가.
   - 상태 갱신과 기록 추가는 **한 번에 저장**된다(둘 중 하나만 저장되는 일 없음).

**복습 대상 목록**(`get_queue`): 다음 복습일이 오늘 이하인 단어를 밀린 날이 오래된 순(같으면 빈도 순위 순)으로 최대 10개 준다. 응답에는 정답 단어가 들어가지 않는다. 남은 대상 수도 함께 준다.

**확인 퀴즈**(`get_check_quiz`): 방금 배운 단어를 요청한 순서대로 최대 10개 낸다. 읽기만 하며, 일정·기록은 바꾸지 않는다.

## 6. 새 단어 학습 — `services/study_service.py`

### 6.1 요금제 범위
- 무료: 빈도 순위 1~250번(설정값 `FREE_WORD_LIMIT`)만 학습 가능.
- 프리미엄(이용권 기간 중): 전체 2,000개.
- 기간이 끝나면 무료 범위로 돌아간다. 이미 배운 단어는 복습할 수 있다.

### 6.2 오늘 더 배울 수
- `오늘 더 배울 수 = min(하루 목표 − 오늘 배운 수, 요금제 범위 안에서 아직 안 배운 수)`, 0 미만이면 0.
- 하루 목표는 **막는 기준이 아니라 목표**다. 목표를 넘겨 평가해도 저장된다. 다만 "오늘 할 것"에는 목표 기준으로 표시된다.
- 요금제 범위 밖을 요청하면 403(`PLAN_LIMIT_EXCEEDED`).

### 6.3 새 단어 목록
- 요금제 범위 안에서 아직 안 배운 단어를 빈도 순위가 **낮은 순**(자주 나오는 단어 먼저)으로 준다.
- 한 번에 최대 10개, 그리고 "오늘 더 배울 수"를 넘지 않는다.

### 6.4 플래시카드 평가 저장
1. 단어가 없으면 404. 요금제 범위 밖이면 403.
2. 이미 배운 단어면 409(`WORD_ALREADY_LEARNED`).
3. 평가 → 점수(3.1) → 첫 SM-2 계산(연속 0 상태에서 시작).
4. 단어 상태 행 추가 + 기록 추가를 한 트랜잭션으로 저장.
5. 저장 사이에 같은 카드가 동시에 들어오면 DB의 기본 키 제약이 막는다 → 409.

## 7. 연속 학습일과 숙련도 — `core_logic/progress_rules.py`

### 7.1 연속 학습일
- 오늘 학습했으면 오늘부터, 오늘은 아직이고 어제 했으면 어제부터 거꾸로 센다. (어제까지 이어졌으면 끊기지 않은 것으로 본다.)
- 하루라도 비면 거기서 멈춘다.
- 같은 날 여러 번 학습해도 하루로 센다.
- **왜 어제부터도 세나**: 아침에 앱을 열었을 때 아직 오늘 공부를 안 했다고 연속이 0으로 떨어지면 학습 의욕을 해친다.

### 7.2 숙련도 구분
- 한 번도 학습하지 않은 단어: **새 단어**
- 간격 21일 미만: **학습 중**
- 간격 21일 이상: **익숙함**
- 21일 기준은 임시값이다(설계 확정, 구현 후 조정 가능).

### 7.3 날짜 경계
- 날짜는 KST 기준으로 자른다. 예: 한국 시간 오전 8시 학습은 UTC로는 전날이지만 KST로는 당일이다. (테스트: `test_utc_morning_before_9am_kst_is_still_same_kst_day`)

## 8. 결제 확인과 환불 — `services/subscription_service.py`

### 8.1 주문 생성
1. 주문번호를 서버가 만든다(`svc-` + 무작위 16자).
2. 금액도 서버가 정한다(클라이언트 값 무시).
3. 상태 `pending`으로 저장.
4. 결제위젯에 넘길 회원 키는 회원 번호와 서버 비밀값으로 계산한다(DB에 저장하지 않음).

### 8.2 결제 확인 (순서가 중요함)
1. 내 주문인지 확인 (아니면 404). 주문 행을 잠근다.
2. 이미 `paid`면 같은 결과를 돌려주고 **이용권은 늘리지 않는다.** (멱등)
3. `failed`나 `canceled`면 402.
4. 요청 금액 ≠ 주문 금액이면 400. **외부 호출을 하지 않는다.**
5. 결제사 승인 확인 (서버 → 토스):
   - 거절이면 `failed`로 저장하고 402.
   - 통신 실패면 **되돌리고** `pending` 유지 → 나중에 다시 확인 가능. (결과를 모르므로 실패로 단정하지 않는다.)
6. 승인되면 한 트랜잭션으로: 상태 `paid` + 승인 시각 + 이용권 연장.
   - 이용권 연장 = max(지금, 현재 만료일) + 30일. 남은 기간 뒤에 이어 붙는다.
   - 회원 행도 잠가서 동시 주문이 날짜를 덮어쓰지 않게 한다.

### 8.3 환불
환불을 막는 조건을 순서대로 확인한다. 하나라도 걸리면 409와 이유를 돌려준다.
1. 이미 환불됨 → 막음
2. 결제 완료 건이 아님 → 막음
3. 가장 최근 결제가 아님 → 막음
4. 승인 후 7일(설정값 `REFUND_WINDOW_DAYS`) 지남 → 막음
5. 결제 이후 무료 범위 밖 단어를 학습함 → 막음 (이용권으로 얻은 혜택을 쓰고 환불하는 것을 막기 위함)

통과하면: 토스 취소 요청 → 성공 시 상태 `canceled` + 이용권 30일 회수(회수 결과가 지금 이전이면 무료로 복귀).
- 결제사 거절이면 402, 통신 실패면 502. 두 경우 모두 상태를 바꾸지 않아 다시 시도할 수 있다.

## 9. 가입 동의와 회원 탈퇴 (요약)

- **가입 동의** (`core_logic/consent_rules.py`, `services/auth_service.py`): 필수 3개와 선택 1개를 받는다. 약관 버전이 서버 값과 다르면 409. 동의 시각과 버전을 기록한다. 마케팅 동의는 나중에 바꿀 수 있다.
- **회원 탈퇴**: 개인 정보(이메일·닉네임)를 지우고 익명 처리한다. 학습 기록은 삭제한다. 같은 이메일로 다시 가입할 수 있다. 다른 회원 데이터는 건드리지 않는다.

## 10. 아직 정하지 않은 것 / 확인이 필요한 것

1. **점수 규칙(D-5)**: 정답 확인을 2점으로 할지는 발표 전 대표 확인이 필요하다.
2. **익숙함 기준 21일**: 임시값이다. 실제 사용 후 조정할지 정해야 한다.
3. **하루 목표 10개**: 설정 기본값 10개는 제안값이다.
4. **세션 중단 후 이어하기(FR-STUDY-05)**: 진행 상황 저장 로직을 이 문서에서 따로 확인하지 못했다. 구현 위치를 확인한 뒤 보완한다.
5. **환불 기간 7일**: 설정값이다. 법무 검토 여부는 확인되지 않았다.
