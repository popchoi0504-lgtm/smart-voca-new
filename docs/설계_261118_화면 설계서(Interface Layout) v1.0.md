# 화면 설계서 (Interface Layout)

**파일 위치**: `docs/설계_261118_화면 설계서(Interface Layout) v1.0.md`
**작성일**: 2026-11-18
**버전**: v1.0 (초안, 대표 검토 전)
**설명**: 화면 전체 목록, 각 화면의 목적과 주요 요소, 화면 사이의 이동 흐름(스토리보드), 공통 상태 처리를 한 문서로 묶는다.

> 방법론 §2 "UI/UX 설계서(Interface Layout)" 초안이다. 옛 버전 방법론 기준.
> 근거: `src/frontend/src/App.jsx`(경로), `pages/`(각 화면 문구), `components/AppShell.jsx`·`teacher/TeacherWidget.jsx`(공통 요소). 화면 모양(색, 간격)은 이 문서에서 다루지 않고 `styles/` 파일과 직접 확인으로 대신한다.
> 화면 확인은 **이 PC에서 서버와 화면을 띄우지 않고** 작성했다. 실제 모습과 다를 수 있다. `[직접 확인 필요]` 표시가 있는 항목은 화면을 띄워서 확인해야 한다.

## 3. 화면별 설명

### 3.1 홈 `/`
- **주요 요소**: 제목 "하루", 오늘의 요약 — 새로 배울 단어 수, 복습 대상 수. "단어 2,000개", "토익 빈출", "간격 복습" 소개 문구. 이동 버튼: 학습 기록, 프리미엄 보기, 설정.
- **상태**: 불러오는 중 → 요약 표시. 요금제 범위 때문에 새 단어가 막힌 경우 "프리미엄 보기" 안내 `[직접 확인 필요]`.
- **이동**: 학습 시작(새 단어 `/study`, 복습 `/quiz`), 학습 기록, 설정, 프리미엄.

### 3.2 새 단어 학습 `/study`
- **주요 요소**: 제목 "새 단어". 플래시카드(앞면 영단어, 뒷면 뜻·예문). 평가 버튼 3개: 몰랐음, 애매함, 알았음.
- **상태**:
  - 불러오는 중
  - 배울 새 단어가 없음: "지금 배울 새 단어가 없어요."
  - 끝: "수고했어요! 🎉" + "이어서 더 배우기" (다음 묶음) + "오늘 할 것으로" (홈)
- **규칙**: 평가 1번이 저장되면 다음 카드로 넘어간다. 하루 목표를 넘어도 막지 않는다(FR-STUDY-04).

### 3.3 복습 퀴즈 `/quiz`, 확인 퀴즈 `/quiz/check`
- **주요 요소**: 제목 "복습 퀴즈" 또는 "확인 퀴즈". 한국어 뜻과 예문 빈칸(`______`). 입력칸 "영단어를 입력하세요". 힌트 패널(1·2·3단계).
- **힌트 규칙**:
  - 1단계: 섞인 글자. 짧은 단어는 "건너뜀" 표시.
  - 2단계: 빈칸 힌트.
  - 3단계: 정답 표시. 이 문제는 오답이 아니라 "정답 확인"으로 기록된다(D-5).
- **제출 후**:
  - 정답이면 다음 문제.
  - 오답이면 정답을 보여주지 않는다(IF-8). 다시 입력하거나 힌트를 쓸 수 있다.
  - 오늘 이미 반영된 단어면 "연습"으로 표시하고 일정은 바뀌지 않는다(IF-4).
- **끝**: "복습 끝! 🎉" 또는 "확인 끝! 🎉", "남은 복습 이어서 하기" 버튼(남은 대상이 있을 때).
- **확인 퀴즈**: 새 단어를 배운 직후 `/quiz/check`로 들어온다. 최대 10개. 복습 일정에 영향을 주지 않는다.

### 3.4 즐겨찾기 `/favorites`, `/favorites/study`
- **주요 요소**: 제목 "즐겨찾기". 목록과 빼기 버튼. 즐겨찾기만 학습하는 `/favorites/study`.
- **상태**: 불러오는 중. 무료 범위 밖 단어는 잠긴 표시 `[직접 확인 필요]`.

### 3.5 학습 기록 `/progress`
- **주요 요소**: 제목 "학습 기록". 섹션 5개:
  1. 오늘 (날짜, 오늘 학습 단어 수)
  2. 전체 진행 (배운 단어 수 / 2,000개)
  3. 숙련도 (새 단어, 학습 중, 익숙함)
  4. 학습 달력 (12주, 날짜별 칸, 칸 위에 "학습함"·"학습 안 함" 설명)
  5. 배운 단어 목록 (펼치기)
- **연속 학습일**: 화면에 표시. 계산 규칙은 프로세스 설계서 7장.

### 3.6 설정 `/settings`
- **섹션**: 프로필(닉네임, 아바타 색), 이용권(요약, 만료일), 학습(하루 새 단어 수), 알림(마케팅 동의 토글), 비밀번호 변경(접힘), 회원 탈퇴(작은 링크, 비밀번호와 확인 문구 입력).
- **규칙**: 회원 탈퇴는 확인 문구를 정확히 입력해야 진행된다. 탈퇴 후에는 로그아웃된다.

### 3.7 프리미엄 `/subscribe`
- **주요 요소**: 제목 "프리미엄". 요금제 두 가지(무료, 프리미엄 30일 4,900원). 주문 후 결제 위젯. 결제 내역 목록(환불 가능 여부 표시).
- **환불 버튼**: 환불 불가 조건이면 사유를 보여준다(FR-SUB 환불 규칙, 프로세스 설계서 8.3).

### 3.8 결제 결과 `/payment/success`, `/payment/fail`
- **성공**: 서버가 결제를 확인한 뒤에만 성공으로 보여준다(FR-SUB-03). 브라우저 결과만으로 성공 처리하지 않는다.
- **실패**: 실패 이유 안내(예: 카드 거절, 통신 실패) 후 다시 시도 버튼.
- **중복 요청**: 새로고침해도 이용권이 두 번 늘지 않는다(IF-6). 화면은 같은 성공 결과를 보여준다.

### 3.9 로그인 `/login`, 회원가입 `/signup`
- **로그인**: 이메일, 비밀번호. 실패 메시지는 어느 쪽이 틀렸는지 알려주지 않는다(FR-AUTH-02).
- **회원가입**: 이메일, 비밀번호, 필수 동의 3개와 선택 1개(마케팅). 가입 후 바로 로그인(IF-3).
- **약관 링크**: `/terms`, `/privacy`.

### 3.10 약관 `/terms`, 개인정보처리방침 `/privacy`, 서버 상태 `/status`, 없는 페이지
- 약관과 방침은 **초안**이다. 정식 출시 전 법무 검토가 필요하다(이슈 #18, CLAUDE.md).
- `/status`: 서버와 DB 연결 확인용이다.
- 없는 페이지: 안내 문구와 홈 이동.

## 4. 스토리보드 (주요 흐름)

```
[로그인] ──성공──▶ [홈 /]
   │                 │
   │ 가입            ├──▶ [복습 퀴즈 /quiz] ──힌트 1→2→3──▶ 제출 ──▶ 다음 문제 ──▶ [복습 끝]
   ▼                 │                                            └▶ 남은 복습 이어서
[회원가입 /signup]   ├──▶ [새 단어 /study] ──평가──▶ 다음 카드 ──▶ [수고했어요]
   │ 자동 로그인      │                                               └▶ [확인 퀴즈 /quiz/check]
   ▼                 ├──▶ [학습 기록 /progress]
 [홈 /]              ├──▶ [즐겨찾기 /favorites] ──▶ [즐겨찾기 학습]
                     ├──▶ [프리미엄 /subscribe] ──결제──▶ [결제 성공 / 실패]
                     └──▶ [설정 /settings]
```

## 5. 공통 상태 처리

| 상태 | 화면에 보이는 것 | 기준 |
|---|---|---|
| 불러오는 중 | "불러오는 중…" | 모든 데이터 화면 |
| 데이터 없음 | 안내 문구 (예: "지금 배울 새 단어가 없어요.") | 빈 목록 |
| 오류 | 사용자가 이해할 수 있는 한 문장. 서버 내부 내용은 보이지 않음 | FR-SYS-01, IF-2 |
| 로그인 만료 | 로그인 화면으로 이동 | 401 응답 |
| 외부 결제 서비스 장애 | "잠시 후 다시 시도해 주세요." | 502 응답 |

## 6. 알려진 제한과 확인할 것

1. **화면 자동 테스트가 없다.** 화면은 직접 확인에 기대고 있다. `[직접 확인 필요]` 항목은 서버와 화면을 띄운 뒤 같은 동작을 2회 이상 확인해야 한다.
2. **모바일 대응은 범위 밖**이다(NFR-USE-02). 데스크톱 Chrome 기준.
3. **AI 선생님 위치**, **발음 버튼 위치**, **출처 표기 위치**는 코드에서 정확히 확인하지 못했다. 실제 화면에서 확인 후 이 문서를 고쳐야 한다.
4. **시연 계정**: 데모 계정으로 모든 화면을 한 번씩 돌려 보는 것을 권장한다(운영 정의서 5.2).
