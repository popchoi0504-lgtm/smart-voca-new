## 상태

**잠정 결정** (대표 승인 2026-11-02). 팀 회의에서 이견이 있으면 이 문서를 v1.1로 갱신한다.

## 배경

- 영어단어 학습 웹 플랫폼을 2주 안에 상용화 가능한 수준으로 제작해야 한다.
- 대표는 Python, SQL, JavaScript를 입문 수준으로 접했고, 모든 선택의 이유를 설명할 수 있어야 한다.
- DB 연동과 배포가 가능해야 한다.

## 대안

| 안 | 구성 | 장점 | 단점 |
|---|---|---|---|
| A | FastAPI + PostgreSQL + 서버 렌더링(Jinja/HTMX) + Docker | 아는 언어 위주라 학습 부담이 가장 적음 | 화면 표현력과 확장성이 제한적 |
| **B (채택)** | FastAPI + PostgreSQL + React | 화면이 현대적이고 프론트·백엔드 분리 구조가 상용 서비스 표준에 가까움 | JavaScript/React를 추가로 학습해야 하며 설명할 범위가 넓음 |
| C | Next.js + Supabase | 가장 빠름, 인증·DB 기성품 | 내부 동작을 이해하기 어려워 "직접 이해" 목표와 충돌 |

## 결정 근거

1. 대표가 JavaScript를 접해본 경험이 있어 B안의 추가 학습 부담을 감수할 수 있다고 판단했다.
2. 프론트엔드(React)와 백엔드(FastAPI)를 API로 분리하면 구조가 명확해 발표에서 설명하기 좋고, 이후 모바일 앱 등으로 확장하기도 쉽다.
3. DB는 PostgreSQL을 사용한다. 대표가 SQL을 배웠고, 상용 서비스에서 가장 널리 쓰이는 오픈소스 관계형 DB다.

## 위험과 완화

| 위험 | 완화 방안 |
|---|---|
| React 학습으로 일정 지연 | MVP 화면 수를 최소화하고, 화면 단위로 하나씩 만들며 설명한다 |
| 설명 범위가 넓어짐 | 컴포넌트·API 단위마다 "한 줄 요약 + 발표용 Q&A"를 문서에 쌓는다 |
| Docker 미설치 | 배포 방식 확정 시 설치하거나 대안(관리형 호스팅)을 ADR-002로 결정한다 |

## 미결정 사항 (추후 ADR)

- 인증 방식 (자체 로그인 vs 소셜 로그인)
- 배포 플랫폼
- 단어 데이터 출처
