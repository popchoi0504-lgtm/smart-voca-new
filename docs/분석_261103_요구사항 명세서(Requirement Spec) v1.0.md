# 요구사항 명세서 (Requirement Spec)

**파일 위치**: `docs/분석_261103_요구사항 명세서(Requirement Spec) v1.0.md`
**작성일**: 2026-11-03
**버전**: v1.0 (초안)
**설명**: smart-voca 의 기능·비기능 요구사항에 고유 ID 를 부여하고, 기획서 항목과의 추적 관계를 정리한 문서

> 이 문서의 요구사항 ID(`FR-…`, `NFR-…`)는 이후 설계서, 코드, 테스트에서 그대로 인용한다. (방법론 §3 추적성)
> `[본인 확인]` 은 본인 결정이 필요한 항목, `[설계 확정]` 은 설계 단계에서 값을 정할 항목이다.
> 표시 없이 "제안"이라 쓴 값은 Claude 가 정한 임시 기본값이며 근거가 약하므로 본인이 조정할 수 있다.

---

## 1. 범위

- 기획서 v1.2 의 6.1 포함 범위 전부를 요구사항으로 만든다. (기획서 D-6: 범위를 줄이지 않음)
- 6.2 제외 항목(인터넷 배포, Docker, 실제 결제, 모바일 대응, 토플·초중고생, 대규모 접속, 약관 초안)은 요구사항에 넣지 않는다.
- 단어는 **2,000개**로 한다. (본인 결정 2026-11-03 에 약 500개로 정했으나, 2026-11-05 에 2,000개 요구로 변경. 출처는 TSL + NGSL, 아래 FR-WORD-01 참고)

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 학습자 | 서비스를 쓰는 사람 (로그인한 사용자) |
| 새 단어 | 학습자가 아직 한 번도 학습하지 않은 단어 |
| 복습 단어 | 복습 시점이 된 단어 (SM-2 가 계산) |
| 세션 | 한 번에 이어서 하는 학습 단위 (짧게 끝나야 함) |
| 간격 반복 | 잊을 만할 때 다시 보여주도록 복습 간격을 늘려 가는 방식 |
| SM-2 | 간격 반복 계산 공식 (본인 결정으로 직접 구현) |
| 이용권 | 구독 기간 동안 프리미엄 기능을 쓸 수 있는 권리 |

## 3. 사용자와 핵심 시나리오

| 역할 | 설명 |
|---|---|
| 비로그인 방문자 | 회원가입·로그인 화면만 볼 수 있음 |
| 무료 학습자 | 로그인한 일반 사용자. 요금제 제한 안에서 학습 |
| 구독 학습자 | 이용권이 유효한 사용자. 제한 해제 |

관리자 화면은 이번 범위에 없다. 단어 데이터는 시드(초기 적재) 스크립트로 넣는다.

핵심 시나리오(하루 5분): 로그인 → "오늘 할 것" 확인 → 복습 단어 퀴즈 → 막히면 힌트 → 새 단어 몇 개 학습 → 학습 기록(연속 학습일) 확인.

### 4.4 퀴즈와 힌트 (QUIZ, HINT)

퀴즈 형식: 한국어 뜻(과 예문 빈칸)을 보여주고 **영어 단어를 직접 입력**한다. 정답은 대소문자와 앞뒤 공백을 무시한다. (본인 확정 2026-11-03: 객관식 보기 방식은 만들지 않음)

| ID | 요구사항 | 근거 |
|---|---|---|
| FR-QUIZ-01 | 복습 시점이 된 단어로 퀴즈를 내고 학습자가 영단어를 입력해 답한다. | 기획 6.1 |
| FR-QUIZ-02 | 입력이 정답이면 정답 처리하고 결과를 복습 계산에 반영한다. | P2 |
| FR-QUIZ-03 | 오답이면 다시 시도하거나 힌트를 쓸 수 있다. | 기획 5.4 |
| FR-HINT-01 | **1단계 철자 섞기**: 정답의 모든 알파벳을 무작위로 섞어 보여준다. 섞은 결과가 원래 단어와 같으면 다시 섞는다. | 기획 5.4 |
| FR-HINT-02 | **2단계 빈칸 힌트**: 철자 위치를 유지하고 일부만 공개, 나머지는 `_` 로 표시한다. 공개하는 글자는 정답의 같은 위치 글자여야 한다. 첫 글자는 항상 공개, 공개 개수는 단어 길이의 약 40%(제안) `[설계 확정]` | 기획 5.4 |
| FR-HINT-03 | **3단계 정답 확인**: 정답을 보여주며, 이때 해당 문제는 오답이 아니라 **"힌트 사용(정답 확인)"으로 별도 기록**한다. | 기획 5.4, D-5 |
| FR-HINT-04 | 힌트는 1 → 2 → 3 단계 순서로만 열 수 있고, 사용한 최고 단계를 문제 결과와 함께 저장한다. | 기획 5.4 |
| FR-HINT-05 | 예외 처리: 글자 수가 3 이하이거나 모든 글자가 같은 단어(예: aa)는 1단계를 건너뛴다. 공백·하이픈이 있는 표현은 구분 문자를 제자리에 고정하고 글자만 섞는다. `[설계 확정]` | 기획 5.4 |
| FR-HINT-06 | 힌트 생성 로직은 화면·DB 와 분리해 단독으로 자동 테스트할 수 있어야 한다. | 기획 5.4, 8 품질 |

### 4.7 구독과 결제 (SUB)

**조사 결과가 설계에 영향을 준다** (환경 분석서 8.1 참고): 토스페이먼츠 공식 문서상 결제위젯 단건 결제는 계약 전에도 개발자 테스트 키로 가능하고 실제 돈은 빠지지 않는다. **자동결제(정기결제)는 계약 후 사용 가능**하며 계약 없는 키로는 `NOT_SUPPORTED_METHOD` 오류가 난다. 따라서 이번 요구사항은 **자동 갱신 없이 "기간제 이용권을 결제위젯으로 구매"하는 방식**으로 정의한다. (본인 확정 2026-11-03)

| ID | 요구사항 | 근거 |
|---|---|---|
| FR-SUB-01 | 요금제는 무료와 프리미엄 두 가지로 나누며, 각 요금제가 허용하는 범위를 정의한다. 범위와 가격은 5장(본인 확정 2026-11-03, 30일 이용권 4,900원). | 기획 6.1, 목적 2.2 |
| FR-SUB-02 | 학습자는 프리미엄 이용권(예: 30일)을 구매할 수 있다. 구매 화면은 토스페이먼츠 결제위젯을 테스트 키로 연동해 사용한다. 실제 결제는 일어나지 않는다. | 환경 8.1 |
| FR-SUB-03 | 결제 승인은 반드시 서버가 결제사 API 로 확인한 뒤에만 이용권을 부여한다. (브라우저 결과만 믿지 않는다) | 기획 8 보안 |
| FR-SUB-04 | 결제 내역(주문번호, 금액, 상태, 시각)을 저장하고 학습자가 확인할 수 있다. | 기획 6.1 |
| FR-SUB-05 | 이용권 만료일을 저장하고 화면에 표시한다. 만료되면 무료 요금제 범위로 돌아간다. | 기획 6.1 |
| FR-SUB-06 | 결제 취소·실패·중복 요청 시 이용권이 잘못 부여되지 않는다. 같은 주문번호로 두 번 부여하지 않는다. | 기획 8 품질 |
| FR-SUB-07 | 자동 갱신(정기결제)은 구현하지 않으며 "계약 후 확장 가능한 구조"로 설명한다. | 환경 8.1 |
| FR-SUB-08 | 결제위젯 연동이 계획대로 되지 않으면 서비스 안의 가짜 결제 화면으로 대체할 수 있도록 결제 부분을 다른 부분과 분리한다. | 환경 5 위험 |

제안 이유: 핵심 학습 기능(복습·힌트)은 무료에서도 쓰게 해서 서비스 가치를 느끼게 하고, 분량과 통계에서 유료 가치를 만든다. 단, 이 구조가 사업적으로 맞는지는 본인 판단이다.

## 7. 수용 기준 예시 (BDD)

핵심 요구사항 3개를 Given/When/Then 으로 적은 예시다. 나머지는 테스트 정의서에서 작성한다.

**FR-HINT-01 철자 섞기**
- Given 정답이 `apple` 인 문제
- When 학습자가 힌트 1단계를 연다
- Then 같은 알파벳 5개를 섞은 글자열이 보이고, 그 글자열은 `apple` 과 같지 않다

**FR-HINT-03 정답 확인**
- Given 학습자가 힌트 3단계까지 열어 정답을 확인했다
- When 결과가 저장된다
- Then 기록에는 오답이 아니라 "힌트 사용(정답 확인)"으로 남는다

**FR-SUB-03 서버 결제 확인**
- Given 결제위젯에서 결제가 성공했다고 브라우저가 알려왔다
- When 서버가 결제사 API 로 해당 결제를 확인하지 못했다
- Then 이용권은 부여되지 않는다
